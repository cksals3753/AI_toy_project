# 챕터 4 · 정차하지 않는 열차 / 3D

챕터 3 출발 객실과 챕터 4의 중앙·후방·선두는 `trainScene.ts`의 같은 객실 구조·재질·좌석·문을 사용합니다. 중앙 객실에서 챕터 4를 시작해도 Canvas·카메라를 다시 만들지 않습니다. 게임 상태·단서·대화·정답·미니게임·하차 판정은 기존 reducer를 유지하며, 장면은 그 상태를 표시합니다. 현재 [챕터 5도 3D로 확장](../chapter5-3d/README.md)했으며 챕터 6은 기존 2D입니다. 아래 챕터 5의 2D 캡처와 전환 검사 결과는 이 문서 작성 당시의 보관 기록입니다.

## 플레이 확인 순서

1. 챕터 3 최종 탑승을 확정하고 출발 대화를 마친 뒤 챕터 4를 시작합니다. 동행 생존자는 중앙 객실 좌석에만 있으며, 단독 탑승 시 등장하지 않습니다.
2. 일반 시점에서 좌석 01 아래 발광 화면을 발견하고 아래를 조준해 유실 휴대폰을 조사합니다. 노선 표시기의 ‘비상 회송 / 정차 요청 없음’도 확인합니다. 움직이는 터널 표시가 창밖을 지나갑니다.
3. 후방 객실 연결문에서 E로 이동해 설명서와 장치함을 조사합니다. 라벨의 R-01 / CAB-R01, X-09 / EXT-X09, P-02 / PWR-P02와 단서 기록을 비교합니다.
4. P-02를 끄면 조명이 꺼지지만 비상등·표식·복구 장치가 남습니다. R-01을 분리하면 선두 패널에 연결 오류가 표시됩니다. 같은 장치함에서 무제한 복구합니다. 외부 송신 연결을 분리하면 기존 일회성 통신 단절·반응 대사가 실행됩니다.
5. 중앙 객실을 거쳐 선두 연결 구역으로 이동합니다. 운전실은 잠겨 있습니다. 정차 요청 패널을 조사하고 기존 신호 동기화 UI를 실행합니다. 오답은 재시도 가능하며 두 번 실패 후 느린 신호 보조를 사용할 수 있습니다.
6. 요청 수락과 감속 대화를 마치면 창밖 움직임이 멈추고 중앙 출입문이 열립니다. 동행 생존자는 중앙 객실의 문 옆 대기 위치로 이동합니다. 후방·선두에 같은 인물이 추가로 등장하지 않습니다.
7. 중앙 출입문에서 문래역 표식과 신발이 놓인 문밖 풍경을 확인합니다. 경고 대화 뒤 역 진입을 보류하거나 승인합니다. 승인하면 챕터 4 완료를 저장합니다.
8. 챕터 5 시작과 기존 휴대폰 프로필 확인을 마치면 3D 문래역 탐색으로 이어집니다. 문밖 장면은 도착 연출이며 새로운 3D 플랫폼 탐색 맵은 없습니다.

## 저장·입력·표현

- 새 `view3d`는 구역·위치·yaw/pitch를 저장합니다. 현재 도착 여부와 NPC 위치를 포함한 `world.ts` 충돌로 카메라를 검증합니다. 운행 중 출입문은 막히며, 도착 후 문턱은 통과할 수 있습니다. 역 이동은 E 조사와 기존 확인창을 통해서만 확정합니다.
- 기존 2D 저장은 단서·자원·연결·미니게임·동행·도착·완료 상태를 유지하고 해당 구역의 안전 위치에서 3D를 시작합니다. 2D x/y를 3D x/z로 사용하지 않습니다.
- E·Tab·I·Esc, 모바일 조이스틱/드래그/조사, UI 일시정지와 복귀, 필수 에셋 로딩 제한·재시도·2D 복귀는 기존 공통 탐색기를 재사용합니다. 모든 필수 조사·연결 복구는 객실 전원 차단 중에도 가능합니다.
- 장치 상태는 색상과 글자 ‘연결/분리’, 패널 상태 문구, HUD로 함께 표시합니다. 세계 안의 표식에는 조작 설명을 넣지 않습니다.
- 터널 이동은 창의 표시만 움직이는 연출이며 실제 열차 물리·카메라 흔들림은 없습니다. 사운드 대신 기존 자막·대화를 유지합니다.
- 기존 Kenney CC0 생존자 모델에 좌석 자세를 적용하고 같은 스킨·초상화·표시 이름을 사용합니다. 캐릭터 파일 바이트는 캐시하며 구역을 나가면 인스턴스·애니메이션·텍스처·이벤트를 정리합니다. 신규 외부 에셋·AI 호출은 없습니다.

## 검증 명령

```sh
npm run build
npm run lint
npm test
npm run format:check
FIRST_PERSON_CHECK=chapter4 npm run test:browser:first
FIRST_PERSON_CHECK=chapter4-controls npm run test:browser:first
FIRST_PERSON_CHECK=chapter4-visual npm run test:browser:first
```

`chapter4`는 챕터 3 승인 완료 체크포인트에서 실제 이동·E·확인창으로 탑승해 진행합니다. 시각 확인용 `chapter4-visual`은 유효한 고정 저장 체크포인트이며 실제 플레이 검증과 구분합니다. 전체 챕터 회귀는 별도 기존 2D 모드입니다.

## 수행 결과와 미확인 항목

- 빌드·TypeScript, ESLint, Prettier 통과. 단위·계약 테스트 14개 파일, 124개 테스트 통과.
- Chrome 3D 플레이: 챕터 3 동일 Canvas 연속성, 세 구역과 필수 조사, 동행/단독, 전원 차단·중계 오류 후 복구, 일회성 반응과 저장, 미니게임 실패·재시도·보조·성공·활성 상태 복원, 정차·하차 확인·완료 복원·챕터 5 연결 통과.
- 기존 2D 경로 챕터 1~6 통합 회귀 통과. 동행/단독, 챕터 5 응답/무응답, 챕터 6 두 경로, 주요 저장·일회성 사건을 확인했습니다.
- PC Tab·I·Esc와 메뉴 중 이동 차단·탐색 복귀 통과. Chromium 모바일 390×844 터치 이동·메뉴 복귀·전체 화면 높이 통과.
- 브라우저의 외부 AI `/api/chat` 요청 0건. 실제 모델 호출 검증을 수행하지 않았습니다.
- 실제 Android/iOS·Safari/Firefox와 하드웨어 GPU의 성능·발열·장시간 메모리는 미검증입니다. Chrome 헤드리스는 SwiftShader를 사용하므로 실기기 검증과 구분합니다.
- 3D 지연 로드 청크 약 737 KB의 크기 경고가 남습니다. 충돌은 기존 2D 사각형이며 객실 연결문은 기존 구역 전환 방식입니다. 실제 추종 AI·전투·3D 플랫폼 확장은 없습니다.
