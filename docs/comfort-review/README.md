# 화면·조작 편안함 검토

## 코드 조사와 변경

Three.js 카메라는 매 프레임 고정 높이 1.5m에 배치하고 사용자의 yaw/pitch만 적용했다. 걷기 bob, roll, 자동 추적 회전, 관성, 모션 블러, 후처리 왜곡, 이동 중 FOV 변화는 없었다. 이를 유지했다. NPC의 대기/걷기 동작과 시설문 충격은 카메라와 별개다.

| 항목               | 기존               | 현재 기본값 / 범위                           |
| ------------------ | ------------------ | -------------------------------------------- |
| 마우스             | 0.0025 rad/px 고정 | 0.0015 / 0.0005–0.004                        |
| 터치               | 0.006 rad/px 고정  | 0.003 / 0.001–0.008, 화면 짧은 변 390px 환산 |
| 세로 FOV           | 64° 고정           | 64° / 55–80°, 가로 40–105° 보정              |
| 플레이어 이동      | 165 월드 단위/초   | 132, 99–165                                  |
| 감염자 순찰 / 추적 | 65 / 115           | 52 / 92, 플레이어와 동일 배율                |
| pitch / 높이       | ±1.1 rad / 1.5m    | 유지                                         |
| 구역 진입          | 로딩 완료 직후     | 로딩 후 240ms 페이드, 입력·위협 정지         |

대합실 감염자·안전 표식 렌더링이 고정 축척 50을 사용하던 불일치를 수정했다. 대합실의 환경·카메라·충돌과 동일한 축척 40을 사용한다. 다른 구역 축척은 기존 그대로다. 이동은 기존 축별 충돌·5단위 이하 소단계·대각선 정규화를 유지한다. 프레임 지연은 최대 50ms까지만 이동에 반영하고 일시정지 시간을 누적하지 않는다.

## 직접 비교 순서

1. `npm run dev` 실행 후 기존 저장을 이어가거나 첫 방을 시작한다. Esc로 커서를 풀고 HUD ? → 화면·조작을 연다.
2. 기본 설정으로 정지 회전, 직진하며 회전, 좌우 이동을 각각 짧게 비교한다. 눈높이나 수평선이 자동으로 흔들리지 않는지 본다.
3. 마우스/터치 감도를 따로 조절한다. FOV 60°·64°·75°를 같은 위치에서 비교한다. 높은 FOV가 항상 편한 것은 아니다.
4. 이동을 60%로 낮추고 벽·문 근처 이동과 대합실 회피를 비교한다. 적도 느려진다. 좁은 화면에서는 화면비 보정으로 실제 세로 FOV가 달라질 수 있다.
5. Tab·I·Esc, 대화·퍼즐을 여닫고 복귀 클릭으로 탐색한다. 새로고침 후 설정·진행이 각각 유지되는지 본다. 기본값 복원은 진행에 영향을 주지 않는다.
6. 모바일에서는 첫 터치로 탐색 복귀 후 새 드래그로 둘러본다. 조이스틱·UI 버튼 터치가 시점 드래그로 이어지지 않는지 본다.

## 자동 검증

- `npm run lint`, `npm test`, `npm run build:playtest`.
- `FIRST_PERSON_CHECK=comfort npm run test:browser:first`: 정지·좌우 이동 중 yaw/pitch/FOV 불변, 설정 즉시 적용, 별도 저장/재로드/복원, 모바일 DPR2에서 기준 50 CSS px 드래그 → 0.15 rad 회전.
- `FIRST_PERSON_CHECK=threat npm run test:browser:first`: 테스트 복원 상태의 이동을 최저 60%로 설정해 기존 실제 감지·추적·붙잡힘·재시도·일시정지·모바일 회피·2D 대체 경로를 검사한다.
- `FIRST_PERSON_CHECK=resume npm run test:browser:first`, `FIRST_PERSON_CHECK=shortcuts npm run test:browser:first`: 기존 E, 메뉴, 키 반복, 잠금 복귀와 퍼즐 검사.

새 설정 브라우저 검사는 실제 UI·마우스·터치를 사용하며 일부 설정 슬라이더 값 변경은 DOM 이벤트로 수행한다. 감염자 집중 검사는 명시적 저장 fixture를 복원한다. 자동 수치/회귀 검사와 사람의 멀미 평가는 별개다.

초기 설정 검사에서 헤드리스 Chrome/SwiftShader의 안정된 정지 화면 100프레임 간격은 p50 약 16.7ms, p95 약 16.7ms, 최대 약 16.8ms였다. 이 표본에서는 급락이 관측되지 않았다. 로딩·전 구역·실제 GPU 성능의 보증이 아니며 변경 전 동일 조건 측정을 확보하지 않았으므로 성능 향상으로 해석하지 않는다. 기존 대형 Three.js 청크 경고는 남아 있으며 초기 모델 로딩·소프트웨어 렌더링 지연과 카메라 입력 문제를 구분해야 한다.

실제 모바일 기기·다양한 GPU·OS 마우스 DPI·신규 플레이어의 멀미 체감은 미검증이다. 신규 에셋과 외부 AI 호출은 추가하지 않았다.

## 이번 검증 결과

최종 단위 검사는 21개 파일, 197개 테스트 통과. 린트·타입/정적 빌드 검사와 변경 파일 형식 검사도 통과했다. 화면 설정 집중 검사, 최저 60% 속도의 감염자 검사, E/잠금 복귀와 메뉴 단축키 검사를 통과했다.

`EPISODE_ARTIFACTS=docs/comfort-review/episode npm run test:browser:production`으로 첫 방 → 대합실 → 승강장 → 열차 → 문래역 → 정비 통로 → 대피소 완료·새로고침·결과 다시 보기를 597초에 통과했다. 새 게임에서 시작해 중간 상태 주입 없이 실제 키/마우스로 진행했다. 이 연속 검사는 NPC 도움·수동 최종 경로 한 가지이며 모든 이야기 분기를 새로 수동 재생한 것은 아니다. 외부 AI/API 요청 0회, 외부 요청·에셋 실패·콘솔 오류 0건이었다. 극단적 화면비의 수치 경계는 추가 단위 검사로 검증했다.

검사 도우미도 새 속도를 읽도록 변경했다. 이전 고정 속도 가정 때문에 가까운 대상의 선택 경계에서 접근이 끝나지 않던 자동화 문제를 보완했다. 저장된 대합실은 안전 안내 대화를 먼저 마친 뒤 단축키를 확인하도록 검사 순서를 맞췄다. 프로덕션에서는 개발 전용 dataset을 요구하는 챕터 2 전용 검사 대신 프로덕션 지원 전체 에피소드 검사를 사용했다.
