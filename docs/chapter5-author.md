# 챕터 5 제작자 설정 — 플레이어에게 직접 노출하지 않음

이 문서는 개발·서사 검토용이다. 게임 UI, 단서 노트, 단톡방, 방송 자막에서 불러오지 않는다.

## 사건의 실제 원인

문래역의 응답형 비상 등록 시스템이 변조되어 있다. 저장된 안내 문장에 수신한 표시 이름을 삽입하고, 구역별 응답 감지 결과를 대기 등록 활성화로 처리한다. 실시간 직원의 목소리, 음성 생체인증, 초자연적 계약이 아니다. 현실 철도·대피 장치와 무관한 게임 전용 규칙이다.

오반장은 비축품 구역으로 사람이 몰리지 않도록 우회 등록을 신청했다. 이때 이전부터 사용하던 단톡방 표시 이름과 B-04 탑승 정보를 수동 첨부했다. 열차 외부 장치 EXT-X09의 전송 묶음에 객실 상태와 별도 등록 첨부가 포함됐다. 챕터 4에서는 기기 화면에 드러난 상태 전송과 시각만 확인했고, 첨부 원본은 문래역 RX-12 수신 단말에서 새로 확인한다. 과거 조사 기록은 바꾸지 않는다.

오반장은 제한된 관리용 등록·상태 화면을 볼 수 있어 챕터 4의 분리 직후 반응했다. 그러나 시스템 전체를 통제하는 사람은 아니다. 대기 구역으로 우회시키는 의도는 있었지만 변조된 차단 절차 전체를 이해한 것은 아니다. 전체 재난이나 시스템 변조의 최종 주체는 이번 챕터에서 확정하지 않는다.

신발은 앞서 도착한 실제 대피자들이 잘못된 ‘침수 오염 방지’ 안내를 따라 벗어 둔 것이다. 바닥 화살표 때문에 방향이 같다. 이전 대피자들은 확인 구역 뒤편의 별도 대기 장소로 이동해 살아 있으며, 챕터 5의 빈 확인실은 다음 응답자를 받는 구역이다. 이들의 현재 위치·안전은 플레이어에게 확정적으로 공개하지 않는다. 신발이 사람으로 변하거나 사람이 그 자리에서 사라지는 초자연 설정은 없다.

## 인물 역할과 공개 제한

- 서윤: 기존의 실제 조력자. 과거 설비 점검 지식으로 경고했지만 현재 현장 설정과 수신 기록은 직접 볼 수 없다.
- 강태오: 기존의 의도적 위험 유도. 구조 확인 절차를 내세워 사용자를 대기 구역으로 보내려 한다. 최종 적이라고 선언하지 않는다.
- 민재: 오래된 직원 호출 버튼 기억을 적용한다. 새 재생 기록이 나오면 기억의 한계를 인정한다.
- 오반장: 자기 이익을 위한 정보 은폐. 사용자가 공개한 기록에만 반응하며 제출 사실을 자백하지 않는다.

플레이어가 확정하는 사실은 ‘누군가 표시 이름과 탑승 정보를 수동 전달했다’까지다. 공개 등록 자료의 제출자 계정은 가려져 있다. 장치 식별자, 차량, 등록 건, 첨부 내용의 대조가 필요하다. 동일 시각만으로 송신자의 신원을 추정하거나 조력자·최종 적을 판정하지 않는다.

## 분기 고정 규칙

응답 분기: 현장 경고 → 명시적 응답 → 확인실 진입 및 차단문 폐쇄 → 내부 등록·해제 안내 조사 → REG-410 취소 → 승강장 복귀 → 안내 부스 증거 대조 → 외부 유도 보류.

무응답 분기: 현장 경고 → 명시적 무응답 → 차단문 미작동 → 안내 부스 증거 대조 → 미확인 REG-410 등록 보류.

공통: M-12 현장 표식 별도 조사 → D-02 / 지역 수동 승인 → 통로 개방 → 분기별 자동 재시도 방송 → 이동 승인 및 챕터 완료. 오답·취소·재조사에 자원을 쓰지 않으며 영구 봉쇄가 없다.

프로필 화면은 과거부터 사용한 게임용 표시 이름을 플레이어에게 확인시키는 장면이다. 확인 시 새로운 개인 자료를 과거로 전송하지 않는다. 기본 이름 ‘한결’ 또는 1~16자의 게임용 이름을 회차에 저장한다. 실제 개인정보·마이크·로그인·외부 서비스는 사용하지 않는다.

챕터 5 완료는 D-02의 이동 승인까지이며 실제 통로 탐색과 에피소드 1 완결은 [챕터 6 제작자 설정](chapter6-author.md)과 연결한다. 제출자 비공개 및 기존 인물 역할은 챕터 6에서도 유지한다.
