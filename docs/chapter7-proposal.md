## 1. 도입과 사건의 실제 배경

대피소는 실제로 마른 바닥·쉴 의자·기본 보급과 문으로 보호되는 지상 공간이다. 지하에서 벗어나 휴식을 취한 것은 에피소드 1의 분명한 성취다. 대피소가 함정이거나 기존 도착 확인이 거짓이었다는 설정은 추가하지 않는다.

이번 구간의 현장 사실은 **외부 물자 반입문의 잠금부가 손상됐고, 후면 지상 비상 통로도 뒤틀린 문 때문에 바로 쓰기 어렵다**는 것이다. 감염자 한 명이 바깥 하역 공간으로 접근한다. 이 접근을 특정 단톡방 인물의 유인이나 시스템 변조와 연결하지 않는다. 감염자의 기원·재난 전체 원인도 확정하지 않는다.

도입 순서:

1. 에피소드 1 결과에서 **‘에피소드 2 시작’**을 명시적으로 누른다. ‘새 게임’과는 다른 행동이며 초기화 확인창을 재사용하지 않는다.
2. 같은 대피소의 휴식 구획에서 시작한다. 정문/측면 해치로 왔다는 이전 경로는 첫 문장·배경 동선에만 반영한다. 측면 해치를 새 지상 비상 출구로 둔갑시키지 않는다.
3. ‘쉬고 몸을 정돈한다’는 명시적 행동과 짧은 페이드로 휴식을 표현한다. 실제로 몇 분을 기다리게 하지 않는다. 동행 NPC 대화 또는 혼자 주변을 확인하는 장면을 이어간다.
4. 실내를 자유롭게 둘러보고 입구 잠금부·후면 문과 물자 위치를 확인한다. 이때는 위협 진행과 방어 시간이 시작되지 않는다.
5. **‘외부 접근 확인’**을 사용하면 관측창 너머 감염자가 드러나는 짧은 장면과 대응 안내가 열린다. 시점을 강제로 돌리지 않는다. 대화 중 문이 깨지지 않는다.
6. 안내에 ‘대응 시작 후 활성 탐색 시간만 흐름 / 메뉴·대화에서는 정지’를 표시하고 **‘현장 대응 시작’**을 눌러야 실제 작업과 방어 시간이 시작된다.

현장 사실은 먼저 보이고, 그 정보를 바탕으로 사용자가 행동을 시작한다. 준비 중 적이 비현실적으로 문을 계속 두드리는데 손상만 멈춰 있는 연출은 피한다. 준비 장면에서는 적을 바깥 접근 동선에 두고, 대응 시작 후 반입문까지 이동시킨다.

## 2. 맵과 기존 대피소 연결

**작은 연결 맵 하나**를 제안한다. 대피소 중앙부는 기존 의자·표식·도착 확인대와 재질을 재사용하고, 챕터 7용 배치에 실내 작업 구획과 좁은 외부 하역 공간만 덧붙인다. 넓은 거리·다른 건물·다음 역은 만들지 않는다.

```text
바깥 하역 공간: 감염자 접근 동선, 관측창으로 식별 가능
                        │
                외부 물자 반입문
                [입구 지지대 설치점]
                        │
             생활 구역과 나누는 방화문
                        │
      물자 선반 ─ 기존 대기 공간·도착 확인대
          │             │
    중앙 우회 동선       짧은 후면 연결 통로
          └───── 뒤틀린 후면 문 ─────┘
                 [비상로 지지대 설치점]
                         │
        후면 준비 구획: 수동 권양 손잡이·방화문 잠금 조작부
                         │
             지상 비상 이동로 입구 / 이번 구간의 끝
```

- 외부 반입문은 **챕터 6의 S-01/S-02와 별개**다. 기존 정비 통로로 되돌아가야 한다고 안내하지 않는다.
- 후면 문을 열면 짧은 연결 동선과 준비 구획에 접근하기 쉬워진다. 중앙 우회 동선은 더 길지만 끝까지 사용할 수 있다.
- 방화문 조작부는 안전한 실내 측에 둔다. 감염자를 향해 직접 달려가거나 문 사이로 몸을 밀어 넣을 필요가 없다.
- 감염자는 시작부터 외부 하역 공간의 고정된 접근 위치에 있다. 플레이어 등 뒤 생성·순간이동은 없다. 외부 문·벽·잔해는 같은 충돌 자료로 표현하고 판정한다.
- 준비 중에는 대피소 실내 전체가 안전하다. 대응 중에도 적은 외부문 바깥에 머무른다. 최종적으로 실내 방화문을 닫아 걸면 후면 준비 구획이 실제로 격리된다. 바닥 색만으로 무적 구역을 만들지 않는다.

구현 시에는 기존 `shelter` 완료 공간을 소급 변경하기보다, **챕터 7 전용 구역 ID 하나**로 같은 대피소를 이어 그리는 방식을 권한다. 기존 완료 저장은 계속 `shelter`에서 열리고, 에피소드 2 진입 때만 짧은 페이드로 새로운 시작점에 놓는다. 좌표·충돌 검증 후 위치를 확정하며 기존 저장 좌표를 새 장애물 안에 그대로 쓰지 않는다.

## 3. 물자 운반·설치 조작

필수 운반 물자는 **접이식 금속 지지대 한 세트**만 둔다. 입구에는 문을 버티는 가로 보강대로, 후면에는 뒤틀린 문을 받치는 지주로 사용할 수 있다. 두 설치점의 형태와 상태 설명에서 용도를 확인한다. 어느 쪽에도 설치하지 않은 채 정답 인물에게 맡기는 선택은 없다.

- 집기: 선반 가까이에서 E/클릭/터치로 ‘지지대 들기’.
- 운반: 기존 이동·시점을 그대로 사용한다. 운반 때문에 이동 배율을 추가로 낮추거나 카메라를 흔들지 않는다. HUD에 ‘지지대 운반 중 · 1/1’만 표시하고 시야를 가리는 큰 손/물체 모델은 필수로 하지 않는다.
- 내려놓기: 선반/고정 거치점에서만 가능하다. 자유 투척·바닥 임의 배치·정밀 물리는 없다. 놓을 수 있는 자리는 미리 표시한다.
- 설치: 선택한 설치점에서 ‘입구 보강에 사용’ 또는 ‘비상로 확보에 사용’을 누른다. 결과·남은 시간에 대한 설명과 취소 가능한 확인창을 표시한 뒤 별도로 확정한다.
- 작업: 확정 후 약 1초의 현장 동작을 사용한다. 이동·메뉴·포커스 이탈로 중단하면 마지막 확정 상태로 돌아가며 물자를 잃지 않는다. 동작 중에는 문·걸쇠가 움직이고 완료 시 충돌이 갱신된다. 플레이어 카메라는 고정 높이·입력 기반 시점을 유지한다.
- 설치 후: 이번 구간에서는 지지대를 다른 쪽으로 옮기지 않는다. 한 물자를 두 곳에 중복 적용하거나 설치/해체로 시간을 반복 충전하는 것을 막는다. 선택하지 않은 쪽은 아래의 고정 장치로 해결한다.

운반 상태는 챕터 7의 현장 물자 위치로 관리한다. **기존 `inventory`에 새 문자열을 임의 추가하지 않는다.** 현재 저장 로더는 기존 소지품 허용 목록을 검사하므로 새 물자를 기존 인벤토리 퍼즐로 넣으면 저장 호환성까지 불필요하게 넓어진다.

## 4. 두 우선순위의 실제 플레이 차이

두 선택 모두 완료 가능한 대응이다. 인물의 조언을 맞혔는지에 따른 정답/오답 분류나 등급은 없다.

| 우선순위             | 즉시 얻는 이점                                                                                | 남는 작업과 위험                                                          | 실제 조작·동선                                                                                                            |
| -------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **입구 방어 먼저**   | 반입문 지지대가 문 압력을 버텨 작업 여유를 늘린다. 보강된 문과 늘어난 유지 여유가 보인다.     | 후면 문은 여전히 걸려 있다. 짧은 길 대신 중앙 우회 동선을 사용한다.       | 선반 → 반입문 설치 → 중앙 우회 → 후면의 고정 권양 손잡이를 두 단계로 조작해 문을 열어 고정 → 방화문 폐쇄/잠금 → 준비 구획 |
| **비상 탈출로 먼저** | 후면 지지대로 문이 고정돼 짧은 연결 통로가 즉시 열린다. 후면 준비 구획에 빨리 도달할 수 있다. | 외부문 보강 여유가 없다. 처음의 유지 시간 안에 생활 구역을 격리해야 한다. | 선반 → 후면 설치 → 열린 짧은 통로 → 안전측 조작부에서 방화문을 수동 폐쇄하고 빗장 고정 → 준비 구획                        |

**대체 수단:** 입구 우선 회차도 후면의 고정 권양 장치로 탈출로를 열 수 있다. 비상로 우선 회차도 기존 실내 방화문을 닫고 잠가 외부 위협을 분리할 수 있다. 두 장치는 현장에서 항상 접근 가능하며 과거 아이템·전화기 배터리·동행 NPC를 요구하지 않는다.

권양/빗장 조작은 ‘고정핀 해제 → 손잡이 조작’처럼 의미 있는 장치 단계로 나눈다. 암호 입력·정밀 타이밍 QTE·키 연타는 사용하지 않는다. 모바일에서는 같은 상호작용 버튼을 두 번 구분해 누르면 되고, 길게 누르기로 단계가 반복되지 않는다.

최종 방화문 잠금은 양쪽 회차에 존재하지만 **언제 안전한 동선을 만들 수 있는지와 그 전에 해야 하는 작업이 다르다.** 입구 우선은 더 오래 버티며 후면 복구를 수행하고, 비상로 우선은 먼저 열린 길을 이용해 안쪽 격리를 서두른다.

## 5. 감염자 위협·시간·안전·실패 복구

### 필요한 만큼만 행동 재사용

기존 감염자 한 명의 순찰·소리 위치 조사·충돌/길찾기·보행 표현을 재사용한다. 준비 중에는 바깥 접근 동선을, 대응 중에는 반입문에서 난 현장 작업음을 향한 이동을 사용한다. 문 소리를 들었다고 실내 플레이어 좌표를 알아내지 않는다. 벽과 닫힌 문 뒤를 투시하지 않으며 물체를 통과하지 않는다.

이번 첫 구간에서는 **적이 실내로 들어온 뒤 전 구역을 추격하는 단계는 넣지 않는다.** 방어 한계 도달을 실패 경계로 삼아 대피소 방어·운반·설치에 범위를 집중한다. 새 전투/공격 입력은 없다. 문 충격은 환경 연출이며 카메라 흔들림이 아니다.

### 국소 유지 시간의 초기 제안값

- 대응 시작 시 외부문 유지 여유 **활성 탐색 120초**.
- 입구 보강 설치 완료 시 **한 번만 120초 추가**. 전체 작업 여유는 최대 240초이며 현재 잔여값이 어떻게 바뀌었는지 표시한다.
- 실내 방화문 폐쇄·빗장 고정이 완료되면 위협이 격리돼 이 유지 시간은 종료된다.
- 외부 관측창의 문 상태, 잠금부 변형, 숫자/단계 HUD, 작은 효과음과 자막을 함께 사용한다. 60/30/15초 지점에 단계 안내를 한 번씩 제공하며 큰 음량·섬광은 쓰지 않는다.
- 메뉴·대화·질문·기록·설정·퍼즐·포커스 이탈·탐색 복귀 대기·전환 페이드에는 적과 유지 시간 모두 정지한다. 오프라인 시간은 반영하지 않는다.
- 유지 여유 0은 즉사/체력 0이 아니다. ‘반입문을 통제할 수 없어 작업을 중단합니다’와 함께 실패 화면으로 전환하고 재시도를 선택하게 한다. 문을 뚫고 나온 적을 눈앞에 새로 만들지 않는다.

120/240초는 구현 전 튜닝 후보이다. **최저 이동 60%·NPC 비동행·낮은 자원으로 필수 작업을 활성 시간 60초 이내에 수행할 수 있는 동선**을 목표로 잡고, 측정 후 최소 두 배 여유를 확보한다. 조건을 만족하지 못하면 맵 동선/유지 여유를 조정하며 달리기·순간이동·적 관통을 추가하지 않는다. UI 읽기 시간은 이 기준에 포함하지 않는다.

### 체크포인트와 재시도

첫 버전은 **‘현장 대응 시작’ 직전 안전한 준비 상태 하나**를 체크포인트로 삼는다. 실패 시 이 지점에서 재시도하며 에피소드 1 결과·현재 자원·휴식 보상·이미 읽은 기록/실제 대화는 보존한다. 이번 대응 시도의 운반/설치/문 작업과 유지 여유만 체크포인트 상태로 복원한다. ‘대응 작업은 시작 전 상태로 돌아갑니다’를 명시해 설치물이 갑자기 복구된 것처럼 보이지 않게 한다.

재시도로 체력·배터리가 깎이거나 기본 물자가 영구 소진되지 않는다. 후반 작업을 잃는 시간이 길어지면 중간 체크포인트를 검토하되, 첫 구현부터 여러 종류의 시도 스냅샷을 만들지 않는다. 현재 규모는 짧은 동선과 두세 장치로 제한한다.

### 낮은 자원으로 시작

휴식 행동 한 번으로 **체력을 최소 30, 배터리를 최소 20%까지** 회복/충전하는 안을 제안한다. 이미 더 높으면 유지하며, 화면에 실제 변화량을 표시하고 한 번만 적용한다. 대피소가 실제 휴식과 보급을 제공했다는 성취도 남긴다. 회복 후 수치는 현재 진행에만 적용하고 에피소드 1 도착 스냅샷에는 반영하지 않는다.

이 보급이 누락된 이전/복구 저장에서도 필수 행동은 체력·배터리·장갑·열쇠를 요구하지 않는다. 메시지당 배터리 차감과 새 행동 소모를 추가하지 않는다. 반복 실패/새로고침으로 회복을 쌓거나 물자를 복제할 수 없다.

## 6. 단톡방과 NPC 동행 분기

단톡방의 네 사람은 현장에 추가 배치하지 않는다. 기존 말투·정보 접근 범위·숨겨진 역할을 유지하고, 이번 장면으로 정체를 공개하거나 새로운 배후를 확정하지 않는다. 대화는 스크립트이며 외부 AI는 계속 비활성이다.

| 인물   | 대화 방향                                                                              | 지식 제한과 후속 질문                                                                                                          |
| ------ | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 서윤   | 현장 문 상태와 조작 위치를 먼저 확인하도록 권하고, 방어와 이동로 확보의 차이를 짚는다. | 사용자가 알려 준 구조만 근거로 조건부 조언. 원격으로 배치나 정확한 유지 시간을 보지 못한다.                                    |
| 강태오 | 입구를 유지하며 대응을 기다리자는 식으로 우선순위를 단정하려 한다.                     | 실제 지원 도착이 확정됐다고 내레이션하지 않는다. ‘지원 확인을 받은 건가요?’라는 질문에는 확답과 추측의 차이가 드러난다.        |
| 민재   | 일반 비상문은 안쪽에서 쉽게 열린다는 과거 경험/상식을 적용한다.                        | 뒤틀림과 고정 상태를 공유받으면 현재 현장은 모른다고 정정한다. 이 대피소에 과거 와 봤다는 새 이력은 만들지 않는다.             |
| 오반장 | 남아 있는 물자와 사용할 수 있는 설비를 먼저 묻고 실무적인 조언을 한다.                 | 사용자가 공유하지 않은 선반 내용·수량·후면 통로를 알고 있지 않는다. 이 대피소의 비축품을 소유했다는 설정을 새로 붙이지 않는다. |

추가 질문은 **현재 입구 상태/후면 상태 확인 → 해당 사실을 질문으로 공개 → 그 사실에 대한 답변** 순서로 해금한다. 단서를 보았다는 이유만으로 모든 인물이 자동으로 알게 하지 않는다. 예: ‘지지대는 한 세트뿐이에요’, ‘후면 문이 뒤틀려 그냥 밀어서는 안 열려요’, ‘지원이 온다는 확인은 받았나요?’.

과거 질문을 하지 않은 회차에 그 답변을 생성하지 않는다. 이전 모순을 다시 묻는 선택은 실제 획득 기록이 있는 경우에만 제공한다. 질문을 생략해도 물리 장치 조작과 챕터 완료는 가능하다. 어느 조언을 택했는지가 아니라 현장 조건과 사용자의 작업이 결과를 만든다.

**동행 NPC:** 에피소드 1 결과의 `npcTogether`·`npcHelp`·`npcLocation`을 진입 기준으로 삼는다. 현재 구역이 대피소라는 이유로 동행을 새로 추정하지 않는다.

- 함께 도착했다면 기존 다친 생존자가 휴식 의자에 있다. helped/invited에 맞는 짧은 감사·현재 상태 대사를 사용한다. 도움은 상호작용 장면의 동작/말로 표현하고, NPC가 없으면 불가능한 운반·장치 조작을 만들지 않는다.
- 추종 AI 대신 준비 단계/후면 확보 뒤의 안전한 장면 전환에서 NPC를 고정 의자로 옮긴다. 이동 경로·문 조작 범위를 막지 않으며 시간 부족 때문에 NPC가 뒤에 남는 선택은 없다.
- 마지막에는 ‘같이 이동할 준비가 됐나요?’라는 정지 대화를 통해 동행 준비를 확인한다.
- 비동행이면 같은 위치에서 혼자 장비/이동 준비를 확인한다. 신도림역에 남은 인물의 위치는 **기존 결과에 기록된 마지막 위치 문장 그대로** 유지한다. 발견하지 않았던 회차까지 비상 부스 의자에 있다고 새로 단정하지 않는다. 구조·사망·대피소 합류도 만들지 않는다.

## 7. 챕터 7 종료 조건과 다음 장면

완료에는 다음을 모두 요구한다.

1. 두 곳 중 한 곳에 지지대를 실제 설치했다.
2. 후면 비상 문이 열린 상태로 고정돼 실제 통행할 수 있다.
3. 생활 구역 방화문이 폐쇄·잠금돼 외부 위협을 분리했다.
4. 후면 준비 구획에 플레이어가 도착했고 동행/단독 준비 확인을 마쳤다.
5. **‘다음 이동 준비 완료’**를 명시적으로 실행했다.

설정 화면을 닫거나 지지대 선택만 했다는 이유로 완료하지 않는다. 외부문 보강 상태·우선순위·확보한 통로·동행 여부를 이번 구간의 작업 기록으로 남기며 점수나 인물 정답표는 없다.

마지막 장면은 대피소 후면 준비 구획이다. 위협은 문 너머로 분리되고 지상 비상 통로가 확보됐다. 플레이어와 동행자는 다음 이동을 준비할 수 있다. **대피소는 휴식과 방어를 제공했고, 사용자의 작업으로 이동 선택지가 늘었다.** 다시 함정/거짓 도착이라는 반전은 없다.

‘챕터 7 완료 · 입구 격리 / 비상로 확보 / 이동 준비 완료’를 표시한다. 후속 이동로 탐색, 새 역·새 인물·챕터 8 진입은 구현하지 않는다. 에피소드 2 전체 완료로도 표시하지 않는다.

## 8. 진입·저장과 기존 엔딩 호환

### 결과 화면과 시작 동작

- 에피소드 1 결과에는 **‘에피소드 2 시작 — 기존 기록을 이어갑니다’**를 별도 버튼으로 둔다. 기존 ‘대피소 보기’와 ‘새 게임’은 다른 위치·문구로 유지한다.
- 시작 확인에는 에피소드 1 결과 보존, 기존 자원/동행 이어받기를 설명한다. 취소하면 현재 결과 화면/대피소로 돌아갈 뿐 진행을 초기화하지 않는다.
- `chapter6.completed`와 유효한 `chapter6.result`가 있을 때만 진입한다. 이미 챕터 7을 시작했다면 새로 초기화하지 않고 ‘에피소드 2 이어하기’를 제공한다.
- 챕터 7 중에도 에피소드 1 결과는 읽기 전용으로 열 수 있다. ‘결과 다시 보기’는 챕터 7 상태나 도착 시각을 바꾸지 않는다. 과거 결과 화면에서 다시 시작 버튼을 누르는 중복 입력도 차단한다.

### 최소 상태 제안 — 아직 코드/필드 없음

| 상태                               | 저장 이유                                                                     |
| ---------------------------------- | ----------------------------------------------------------------------------- |
| 시작·휴식 적용·현재 단계·완료      | 명시적 진입, 보급/사건 중복 방지                                              |
| 우선순위                           | 최초 설치 확정 결과. 확정 전에는 미선택                                       |
| 지지대 위치                        | 선반/운반 중/입구 설치/후면 설치 중 하나. 전역 소지품에 중복 보관하지 않음    |
| 후면 문 작업 단계·방화문 작업 단계 | 마지막 확정 걸쇠/고정 상태에서 재개                                           |
| 문 압력의 누적 활성 시간           | 현재 단계에서 실제 남은 유지 여유 복원. 온라인 실제 시각 차이로 계산하지 않음 |
| 준비 시점 체크포인트·시도 식별값   | 재시도 시 챕터 7 작업 상태만 복원하고 배우를 전환 중 재배치                   |
| 동행자의 현재 준비 위치/확인 여부  | 에피소드 1 동행 기록을 이어받되 현재 준비 상태는 별도 관리                    |
| 도입/경고/종료 연출의 처리 기록    | 새로고침·다시 보기로 메시지/보급/효과음 중복 실행 방지                        |

필요한 새 사실은 기존 `clues`/`asked`/`messages`와 읽음 처리에 추가한다. 같은 사실의 발견/질문 여부를 챕터 7 필드에도 중복 저장하지 않는다. 스크립트 질문 자체가 공개한 사실을 명확히 남긴다. 발견 기록과 공개 기록이 달라야 하는 경우에만 챕터 7용 작은 공개 사실 목록을 둔다. 챕터 2 전용 AI 문맥에 억지로 섞지 않는다.

카메라 임시 애니메이션, 터치 pointerId, 적 좌표·경로·수색 타이머, 1초 조작의 임시 진행률은 영구 저장하지 않는다. 재로드 시에는 안내/페이드로 안전한 실내 시작점에 놓고 적은 보이지 않는 외부 시작점에서 복원한다. **현재 작업 확정 상태와 남은 유지 여유는 그대로**이며, 사용자가 ‘계속’을 누르기 전까지 멈춘다. 이미 시작했던 시도를 새로고침으로 새 준비 시도/추가 120초로 바꾸지 않는다. 명시적인 재시도만 준비 체크포인트로 돌아간다.

### 실제 수정이 필요한 연결 지점

1. 새 `chapter7` 기본값/정규화를 기존 저장 키에 추가한다. 필드가 없는 완료 저장은 ‘에피소드 1 완료 / 에피소드 2 미시작’으로 복원한다. 완료 플래그만 있고 결과가 잘못된 저장은 새 결과를 만들어 채우지 않고 기존 도착 확인 복구 절차를 이용한다.
2. 챕터 7 진입과 입력을 **완료된 챕터 6의 입력 소비보다 먼저** 처리한다. 기존 대화/퍼즐 입력 차단은 유지한다. `chapter6.completed=false`로 되돌려 우회하지 않는다.
3. 결과 자동 표시 효과는 ‘에피소드 1 완료이고 챕터 7 미시작’일 때로 한정한다. 챕터 7을 이어갈 때 결과 화면이 매번 가로막지 않게 한다.
4. 챕터/목표/위치 표시, 상호작용 분기, 질문 선택은 챕터 7을 우선한다. 기존 `chapter6.completed`를 이유로 모든 질문을 막는 UI 조건도 장별로 분리한다.
5. 새 구역·단서·질문 ID를 저장 검증 허용 목록과 월드/뷰 좌표 정규화에 함께 등록한다. 허용 목록 누락으로 전체 저장이 초기화되는 일을 막는다.
6. 인물 배치는 챕터 7 동행 위치를 사용한다. `chapter3.npcBoarded`만 보고 NPC를 과거 의자나 모든 구역에 중복 생성하지 않는다.
7. 멀미·밝기·조이스틱 설정은 현재 별도 저장을 그대로 읽는다. 새 회차 초기화 경로를 에피소드 2 진입에 호출하지 않는다.

`chapter6.result`는 이후에도 불변 스냅샷으로 취급한다. 휴식으로 자원이 늘고 새 대화를 해도 원래 자원·단서 전문·메시지·질문·동행·완료 시각은 동일해야 한다. 에피소드 2 전체 결과 아카이브/DB를 지금 만들 필요는 없다.

## 9. 에셋·구현 단계·검증

### 최소 에셋과 표현

기존 대피소 구조·의자·보관함·생존자 모델/초상화·감염자 관절 보행과 Web Audio를 재사용한다. 문·금속 지지대·걸쇠·권양 장치·설치 소켓·관측창은 용도가 구분되는 프로젝트 제작 저폴리 메시로 보완한다. 기존 시설 표면/거리 체계를 사용하고 챕터 7 대상만 개별 등록한다.

새 3D 손, 운반 중 카메라 흔들림, 외부 다운로드·유료 모델·실시간 물리·파괴 시뮬레이션은 필수가 아니다. 기존 Kenney CC0 파일과 출처는 [에셋 기록](../public/art/README.md)을 유지한다. 새 외부 에셋은 아직 선정/다운로드하지 않았으며 추후 필요할 때만 사용·수정·배포 조건을 확인한다.

현재 밝기·감도·FOV·최저 이동 배율·동적 조이스틱을 유지한다. 작업대/설치점/문 손상/적 실루엣은 밝기 최저값에서도 구분돼야 한다. 위험 표시는 색 외에 숫자·문 상태·아이콘·자막을 포함한다. 소리를 꺼도 같은 정보를 얻는다.

### 권장 구현 순서

1. **완료 저장 연결:** 시작/이어하기, 결과 자동 열기 조건, reducer 순서와 장별 UI 우선순위를 먼저 연결하고 스냅샷 불변 테스트를 작성한다.
2. **위협 없는 작업 흐름:** 같은 대피소 맵, 휴식/단독·동행 도입, 지지대 운반/설치, 두 경로의 고정 장치와 완료 조건을 구현한다.
3. **국소 위협:** 챕터 7용 위협 배치/경로/문 소리 지점을 프로필로 분리한다. 현재 챕터 2의 하드코딩과 섞지 않고 기본 동작은 회귀 보존한다. 문 압력은 게임 코드, 표현은 렌더러가 담당한다.
4. **재시도·저장:** 활성 시간과 마지막 확정 작업 단계, 안전한 재로드·중복 방지를 연결한다. 대화/메뉴/포커스 정지와 전환 후 입력 초기화를 검증한다.
5. **스크립트·표현:** 공유 사실별 질문, NPC 위치 전환, 문/물자 애니메이션·자막·소리를 붙인다. 실제 최저 이동 배율의 소요 시간으로 초기 유지 여유를 조정한다.

현재 지침의 ‘챕터 3 이후 위협 비활성’은 기존 에피소드 1을 보호하는 규칙이다. 향후 이번 안을 구현할 때는 **챕터 1–2와 챕터 7만 허용**하도록 구역별 범위를 명시하고 챕터 3–6의 비활성은 유지한다. 이번 기획 작업에서 그 지침이나 활성 범위를 바꾸지는 않는다.

### 검증 기준

- 정문/자동 복구 해치 경로의 기존 완료 저장에서 각각 시작 가능. 결과 열람/시작 취소/중복 시작으로 기존 결과나 회차를 변경하지 않음.
- 체력 0/1·배터리 0·과거 아이템 없음·선택 단서 누락 상태로 두 우선순위 모두 완료. 휴식은 한 번만 적용되고 재시도로 영구 자원 손실/물자 복제 없음.
- NPC 동행 helped/invited, 비동행 directed/waiting/found, 이전 마지막 위치 기록 없음의 각 경우에 배치/대사/기록 일관성 유지. 동행자를 버리는 선택 없음.
- 집기/내려놓기/설치 확정/동작 중단/문 단계/실패/종료 직전·직후 저장과 이어하기. 문 압력은 오프라인·메뉴·포커스 이탈 동안 증가하지 않음.
- 보강 추가 시간은 한 번만 적용. 설치 취소는 물자를 잃지 않고, 이미 설치된 지지대의 위치/충돌/표현이 서로 일치함.
- 감염자는 출입문/벽을 통과하거나 숨은 플레이어를 따라가지 않음. 실패/재로드의 재배치는 안내/전환 중에만 하며 문 앞/플레이어 옆 생성 없음.
- 모든 조작은 PC E/클릭과 모바일 버튼으로 가능. 보조 손가락 메뉴 닫기·pointer cancel·복귀 클릭·Tab/I/Esc·중첩 UI 정지를 유지함.
- 최저 이동 배율에서 실제 필수 동선 시간과 문 유지 여유를 측정. 모바일 에뮬레이션과 실제 기기/신규 플레이어 검증은 별도로 보고함.
- 기존 검사 명령으로 게임/저장/접근성 회귀, 빌드·린트와 프로덕션 프리뷰를 검사. 챕터 1–6·에피소드 1 재열람, 외부 AI/API 요청 0회를 유지함.

위 수치·배치는 구현 전에 확정한 판정이 아니라 검증 가능한 초기 설계값이다. 이번 결과물은 이 제안서이며 챕터 7 플레이 기능은 아직 없다.
