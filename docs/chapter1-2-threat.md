# 챕터 1~2 생존 위협

## 적용 범위와 플레이 순서

챕터 1의 임시 봉쇄문과 챕터 2의 감염자 한 명을 추가했다. 감염자의 기원·재난 원인·단톡방 인물의 비공개 설정은 추가하거나 변경하지 않았다. 전투·무기·달리기·웅크리기·상시 제한 시간은 없다. 챕터 3부터는 감염자 판정을 실행하지 않는다.

1. 첫 방에서 몸을 일으키면 봉쇄 시설문 바깥의 충격·그림자를 알리고 오반장이 탈출을 경고한다. 시설문은 별도의 배경 시설이며 기존 서쪽/동쪽 선택과 혼동하지 않도록 표식을 붙였다.
2. 탐색 시작과 첫 방 단서 획득에 따라 문짝 흔들림·그림자·먼지·충격음을 한 번씩 발생시킨다. 오래 머물렀다고 문이 뚫리거나 자원을 잃지는 않는다. 읽음·재조사·이어하기는 이미 완료한 충격음을 재생하지 않는다.
3. 기존 단서 대조와 정비문 퍼즐을 마쳐 대합실로 이동한다. 상단 벤치 주변을 순찰하는 감염자를 관찰하며 안내도·점검창·개찰구 안내·데스크를 조사한다.
4. 안내 데스크에서 열쇠를 얻고 아래쪽 IS-02 셔터의 빗장을 해제한 뒤 올림·걸쇠 고정을 완료해 전기실로 들어간다. 전기실은 문으로 분리된 안전 구역이다. 대합실 바닥 표식은 출입구를 찾는 용도이며 감염자를 막거나 플레이어를 보이지 않게 하지 않는다.
5. 기존 세 장치 중 최대 두 개를 켜는 전원 퍼즐을 푼다. 개찰구 소리를 들은 감염자는 플레이어가 아니라 개찰구 위치를 확인한다. 조사 후 다시 순찰하므로 통로를 계속 지키지 않는다.
6. 조명·개찰구 조건을 갖춰 통과한다. 감염자는 대합실에 남으며 계단의 기존 발소리 사건과 챕터 3~6 및 엔딩은 유지한다.

직원 통로의 방화문 미니게임도 유지한다. 미니게임·결과 대화 중 위협은 정지한다. 해당 결과 확인 후 감염자는 기존 런타임에서 재개하고 플레이어는 기존 복귀 위치에 놓인다. 기존 일회성 피해는 감염자 재시도와 별개이며 다시 차감하지 않는다.

## 행동과 판정

판정은 `src/game/threat.ts`, 공통 탐색 연결은 `src/components/useThreat.ts`, 3D 표현은 `src/game/threatVisual.ts`, 2D 표현은 `renderWorld.ts`가 담당한다.

| 항목                | 실제 초기값                                            |
| ------------------- | ------------------------------------------------------ |
| 플레이어 최대 속도  | 초당 165 좌표 단위                                     |
| 순찰·수색·복귀 속도 | 초당 65                                                |
| 추적 속도           | 초당 115                                               |
| 시야 거리           | 230                                                    |
| 시야각              | 전체 120도                                             |
| 발견 확정           | 시야 안에서 1.1초                                      |
| 붙잡힘              | 추적 상태에서 거리 28 미만·시야 연결 상태가 0.8초 지속 |
| 도착 후 수색        | 3.5초                                                  |
| 길찾기 격자         | 20 단위, 기본 경로 재계산 간격 0.6초                   |
| 한 번의 활성 갱신   | 최대 0.05초, 지연된 시간을 몰아서 적용하지 않음        |

순찰 → 의심 → 추적 → 수색 → 복귀 순으로 동작한다. 놓친 뒤에는 마지막 목격 위치로 이동하고 주변을 살핀다. 시야가 가려진 플레이어의 현재 좌표를 목적지로 갱신하지 않는다. 수색 중 실제로 다시 보이면 재감지할 수 있다. 일반 플레이어 발소리에 대한 청각 추적은 없다.

길찾기와 이동은 `world.ts`의 `walkable`과 같은 반경 13의 충돌 기준을 사용한다. 문·사물·기둥·벤치를 통과하지 않는다. 낮은 벤치는 이동만 막으며, 높은 기둥·데스크 시설·닫힌 문은 시야도 막는다. 감염자를 플레이어의 고정 벽으로 등록하지 않아 필수 조사 대상 앞을 영구적으로 가로막지 않는다. 근접 위험은 별도의 붙잡힘 판정으로 처리한다.

새 장면 생성 시 플레이어와 감염자 기본 위치가 180 미만이면 더 먼 고정 순찰 지점에서 처음 배치한다. 화면에 이미 보이는 감염자를 실시간으로 순간이동시키지 않는다. 로딩·구역 전환·직원 통로 장면 전환·재시도에서만 초기 배치를 적용한다.

## 읽기·일시정지·입력

대화·휴대폰·단서 메뉴·퍼즐·전환·붙잡힘 창과 포커스 이탈·백그라운드·3D 탐색 복귀 대기 중에는 감염자 이동·감지·수색이 진행되지 않는다. 일시정지 시 근접 누적은 비우므로 UI를 닫자마자 이전 접촉 시간이 이어져 붙잡히지 않는다. 닫기 후에는 기존 마우스 잠금/클릭 복귀 규칙을 사용한다.

대합실의 필수 조사 전문은 기존 초상화 대화창으로 읽으며 탐색과 위협이 함께 정지한다. 첫 방 짧은 현장 기록은 비차단 방식으로 유지한다. 메뉴 정지는 의도된 규칙이며 사용 페널티나 강제 추격은 없다.

위험 단계는 아이콘·한국어 자막·움직임으로 표시한다. 발견/추적 경고와 가까운 감염자의 발 끄는 소리는 기존 Web Audio 믹서·음소거·볼륨 제어를 따른다. 섬광은 추가하지 않았다.

## 실패·저장 호환성

붙잡히면 창을 표시하고 사용자가 재시도를 선택한다. 전기실 방문 전에는 대합실 입구, 방문 후에는 전기실 내부로 복귀한다. 체력·배터리·단서·소지품·질문·전원 설정·완료된 사건을 보존하고 보상·피해를 다시 적용하지 않는다. 재시도 안내 대화가 끝나기 전에는 탐색이 재개되지 않는다.

영구 저장에는 체크포인트, 경계 중인지 여부, 붙잡힘, 개찰구 소리 처리, 첫 방 연출 단계와 재시도/장면 재개 식별값만 추가했다. 이동 경로·적 좌표·수색 타이머는 저장하지 않는다. 추격/의심/수색 중 이어하기와 초기 적 위치에 지나치게 가까운 새 저장은 안내 후 체크포인트에서 재개한다. 안전한 저장은 기존 위치를 유지한다. 오프라인 경과 시간은 계산하지 않는다.

과거 저장에는 기본값을 적용한다. 챕터 3 이후 회차와 결과 스냅샷을 옮기거나 초기화하지 않는다. 새로 로드한 과거 대합실 저장도 최초 적 배치 거리를 검사한다.

## 외형·에셋

새 감염자는 프로젝트 코드로 제작한 저폴리 관절 인물이다. 별도 외부 다운로드는 없다. 회녹색 피부·주황갈색 손상 작업복·기울인 머리·감염자 표식을 사용해 기존 오반장과 생존자 모델에서 구분한다. 이동한 거리에 맞춰 어깨·다리 관절의 보행 주기를 계산하며, 대기 FBX를 그대로 미끄러뜨리지 않는다. 정지·메뉴 중에는 보행 진행도 정지한다. 이 방식은 모션 캡처나 정교한 발 접지/무릎 애니메이션을 제공하는 것은 아니다.

봉쇄문·그림자·먼지·안내 텍스처와 효과음은 코드로 제작했다. 기존 Kenney CC0 모델과 라이선스는 변경하지 않았다. 출처는 `public/art/README.md`를 따른다.

## 검증 실행

```sh
npm test
npm run lint
npm run build:playtest
FIRST_PERSON_CHECK=threat npm run test:browser:first
PRODUCTION_CHECK=1 FIRST_PERSON_CHECK=threat node scripts/verify-browser.mjs
npm run test:browser:production
```

위협 집중 검사는 낮은 자원의 테스트 저장을 주입한 뒤 실제 탐색 입력으로 발견·붙잡힘·재시도, 메뉴 정지, 추격 저장 복구, 전기실/개찰구, 터치 회피, WebGL 손실 후 2D 이동을 검사한다. 전체 에피소드 검사는 새 게임부터 실제 입력으로 이어지며 붙잡히면 실제 재시도 버튼으로 복귀한다. 두 검사는 상태 주입 여부가 다르므로 결과를 구분한다.

실제 모바일 기기·실제 GPU/스피커·신규 플레이어의 이해도·다양한 모바일 동선의 난이도는 별도 검증이 필요하다. 한 번의 터치 회피 성공이 모든 모바일 환경의 난이도를 보장하지 않는다. 전원 복구 후에도 시간 제한은 없으며 적의 순찰 변화를 보고 이동할 수 있다.

## 검증 결과 (2026-10-23)

[검증 기록](threat-review/verification.json), [첫 방](threat-review/01-first-room.png), [감염자 외형](threat-review/02-infected.png), [붙잡힘](threat-review/03-caught.png), [모바일](threat-review/04-mobile.png), [2D 붙잡힘](threat-review/05-2d-caught.png).

빌드·린트·게임/저장/접근성/AI 계약 검사가 통과했다. 개발 Chrome에서는 실제 추격 중 보행 관절 자세 변화와 메뉴/포커스 정지 중 적 위치 고정을 확인했다. 최종 프로덕션 집중 검사에서는 3D 두 번의 붙잡힘·재시도, 2D 실제 붙잡힘, 긴 단서 읽기 정지, 추격 저장의 안전 복원, 체력 1·배터리 0에서 전원 조작, 모바일 이동·시점 드래그 회피를 확인했다. API·외부 요청·최종 에셋 오류는 없었다.

프로덕션 전체 회귀는 새 게임부터 상태 주입 없이 직원 통로 실패·대합실 탈출·동행 NPC·챕터 3~6·수동 경로 엔딩·완료 결과 저장/재열기까지 488초에 완료했다. 이후 벽 모서리/근접 판정을 보강했으며 해당 변경은 단위 검사와 최종 집중 프로덕션 검사로 확인했다. 모든 선택 분기를 프로덕션에서 다시 플레이한 것은 아니다. 기존 개발 기준 캡처는 유지하고 이번 전체 캡처는 임시 폴더 `last-transfer-ch5-RibDaP/episode-captures`에 보관했다.

## 챕터 2 재구성 후 보완 (2026-10-25)

[침수·셔터 구현 기록](chapter2-restructure/README.md)이 현행 대합실 동선을 설명한다. 물은 공통 충돌에 포함되지만 불투명 은폐물로 처리하지 않는다. 상단 기둥과 IS-02 앞 차폐판에서 시야를 끊을 수 있다. 전기실에서는 적 런타임이 정지하며 왕복 시 동일 런타임을 이어 사용한다. 문 출입으로 감염자를 먼 곳으로 재배치하지 않는다. 체크포인트 재시도·로드는 기존 안전 초기 배치를 사용하며 적 좌표를 영구 저장하지 않는다.
