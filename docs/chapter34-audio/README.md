# 챕터 3–4 합성 사운드

첫 방에서 사용자가 확인한 기본 음량 35%와 기존 WebAudio 설정·재생 허용·음소거·설정 저장을 재사용합니다. 실제 철도 녹음이 아닌 게임용 합성 효과음입니다. 외부 음원·음성·마이크·외부 AI는 사용하지 않습니다.

## 실제 사건에 연결한 소리

| 장면             | 상태·재생 기준                                                                                                 |
| ---------------- | -------------------------------------------------------------------------------------------------------------- |
| 승강장·열차 A    | 낮은 환풍·먼 터널 느낌의 필터 노이즈와 설비음                                                                  |
| 탐색 발걸음      | 기존 충돌 처리 후 실제 이동 거리. 메뉴·대화·퍼즐·벽에 막힌 동안 추가 재생 없음                                 |
| 운행 승인        | `chapter3.approved` 최초 완료                                                                                  |
| 비상 호출·문     | 비상 호출의 기존 응답, B-04 실제 문 개방                                                                       |
| 탑승·출발        | 최종 탑승 확정 뒤 문 폐쇄·출발 효과음, 주행 루프 시작                                                          |
| 기존 추가 발소리 | 챕터 2 끝 계단의 “멈춘 뒤에도 한 번 더” 자막이 현재 대사가 되는 순간 한 번. 승강장에 새로운 사건을 만들지 않음 |
| 진동             | 챕터 4 도입의 유실 휴대폰 진동 사건 한 번. 재조사에는 없음                                                     |
| 객실 설비        | 중앙·후방·선두의 필터 음색과 실제 객실 전원 상태                                                               |
| 연결·분리        | 통신 장치 연결 상태가 실제 바뀔 때 스위치음. 객실 전원 복구 시 복구음                                          |
| 정차             | 동기화 성공 시 요청 접수음, 감속 대사 진입 시 감속음, `arrived` 전환 시 정차·출입문 개방음                     |

열차 A의 문은 원래 열린 상태이므로 들어가거나 나오는 행위만으로 문 소리를 만들지 않습니다. 오답·조사·취소·닫힌 문에 대한 반복 입력은 실제 장치 상태 변화와 구분합니다. 기존 스토리·퍼즐·NPC·자막·시각 안내는 변경하지 않습니다.

## 연속성과 저장

- 주행은 객실 설비 버스를 우회하는 별도 루프입니다. 챕터 3→4 및 중앙↔후방↔선두에서 같은 재생 소스를 유지하며 처음부터 다시 시작하지 않습니다.
- 객실 전원 차단은 설비음을 낮추지만 주행은 유지합니다. 정차 완료 시 주행 소스를 종료하고, 챕터 5 이탈 시 컨텍스트를 정지합니다.
- 탭 숨김·포커스 이탈 시 컨텍스트 일시정지 및 일회성 효과음 정리. 복귀 시 지난 효과음은 재생하지 않습니다.
- 저장된 상태를 초기 비교 기준으로 사용합니다. 출발·진동·승인·감속·정차·문 효과음은 이미 완료한 상태를 불러오면 재생하지 않습니다. 달리는 저장은 주행만 복원하고 정차 저장에는 주행 소스를 만들지 않습니다.
- 사건 소리는 상태 간 차이를 읽기만 하며 게임 판정·자원·저장 형식을 변경하지 않습니다. 브라우저가 소리 재생을 거부해도 게임은 계속됩니다.

## 직접 소리 확인 순서

1. 챕터 2 계단 마지막 대사를 넘겨 추가 발소리가 해당 자막에서만 나는지 확인합니다.
2. 승강장에서 이동·정지·메뉴 열기를 비교하고 열차 A 내부 조사 후 복귀합니다.
3. 비상 부스에서 오답 후 올바른 운행 승인을 요청하고, 비상 호출로 B-04 문을 엽니다.
4. NPC 도움·대기 중 한 가지를 선택한 뒤 최종 탑승을 확정합니다. 챕터 4 시작 전후에 주행음이 중복되거나 다시 출발하지 않는지 듣습니다.
5. 중앙→후방→선두를 왕복합니다. 장치함에서 객실 전원 차단·복구, 중계기 분리·복구, 외부 송신 분리를 확인합니다. 전원 차단 중에도 주행음은 계속되어야 합니다.
6. 정차 동기화 실패·재시도 후 성공합니다. 요청→감속 대사→정차·문 개방 순서를 확인합니다.
7. 정차 저장을 새로고침해 이어갑니다. 출발·감속·진동이 다시 울리지 않아야 합니다. 문래역 하차 후 챕터 5에서는 이전 소리가 남지 않아야 합니다.
8. 진행 중 음소거·음량 저장·탭 이탈 및 복귀, NPC 동행·비동행을 확인합니다.

## 검증

```sh
FIRST_PERSON_CHECK=audio34 npm run test:browser:first
FIRST_PERSON_CHECK=audio npm run test:browser:first
npm test
npm run build
npm run lint
```

`audio34`는 기존 챕터 3·4의 체크포인트 기반 3D 브라우저 검증을 재사용하고 실제 상태 변화와 WebAudio 소스 생명주기를 계측합니다. 새 게임부터 엔딩까지의 연속 무주입 검사는 이번 범위에서 수행하지 않습니다.

### 실행 결과

- `npm test`: 18개 파일·164개 테스트 통과. 신규 4개 테스트에서 실제 reducer의 호출·탑승·NPC 분기·전원 차단·복구·감속·정차·기존 발소리 시점과 저장 상태의 무재생을 확인했습니다.
- `npm run build`: 타입 검사·프로덕션 빌드 통과. 기존 Three.js 지연 청크 약 755kB 경고는 유지하며 경고 임계값은 변경하지 않았습니다.
- `npm run lint`, 변경 파일 Prettier, `git diff --check` 통과.
- `FIRST_PERSON_CHECK=audio34`: 챕터 3·4 기존 3D 플레이와 오디오 계측 통과. NPC 도움·초대·대기/비동행, A-17 왕복, 승인 오답·수정·호출·최종 탑승, 3→4 객실 연속성, 전원·중계기 오류·복구, 동기화 실패·느린 보조·성공, 정차·문래역 하차·챕터 5 진입, 기존/3D 저장·모바일 터치 확인.
- 12개 문서 수명주기·25개 계측 지점에서 문서별 컨텍스트 최대 1개, 실제 오디오 PCM의 0이 아닌 출력, 동일 주행 버퍼의 챕터 전환·전원 변경 유지, 정차 시 주행 소스의 실제 종료를 확인했습니다. 복원한 진행 상태의 출발·진동 등 일회성 사건이 다시 기록되지 않았습니다. 외부 AI 요청 0회, 런타임 예외 0건입니다.
- `FIRST_PERSON_CHECK=audio`: 기존 첫 방·챕터 2 오디오 회귀 통과. 실제 출력·발걸음·메뉴 중지·열쇠 재조사·위험 사건·전원·개찰구·저장 복원·왕복·음소거·음량 저장·실제 탭 전환·모바일 터치 잠금 해제 및 음소거를 확인했습니다. 현재 챕터 3의 환경음 지속도 확인하며, 이전의 챕터 3 무음 기대값은 현 범위에 맞춰 수정했습니다. 외부 AI 요청 0회, 런타임 예외 0건입니다.
- [소스·상태·PCM 계측 기록](result.json). 모든 수치는 합성 오디오 그래프 검사이며 직접 청감 판정이 아닙니다.

초기 검증에서는 설비 오실레이터를 버퍼 루프와 혼동한 개수 기대값과, 정차 저장 복원 후 아직 생성되지 않은 컨텍스트를 실패로 보던 기대값을 수정했습니다. 저장된 퍼즐의 실제 오디오 검증에는 프로그램 방식 `.click()` 대신 브라우저의 실제 클릭 입력으로 재생을 허용하도록 보완하고 전체 검사를 다시 통과했습니다.

## 청감·기기 제약

헤드리스 Chromium의 실제 WebAudio 그래프·출력 샘플·재생 소스를 확인하는 검사와 사람이 듣는 청감 검사를 구분합니다. 첫 방 기준 음량은 사용자 승인 상태지만 챕터 3–4의 스피커·헤드폰 음량 균형, 실제 iOS/Android·Safari·블루투스 출력은 직접 확인이 필요합니다. 합성음은 실제 철도 장치 소리를 재현하지 않습니다. 공간별 환경음은 제공하지만 3D 위치별 음원·벽 너머 소리 감쇠는 구현하지 않습니다.

## 이후 확대

챕터 5 무음 관련 표현은 당시 적용 범위입니다. 현재 챕터 5–6과 엔딩까지 확대했습니다. `audio34`는 문래역 진입 시 주행 소스 잔류가 없는지 확인하고, [챕터 5–6 사운드](../chapter56-audio/README.md)에서 환경음·등록·배수·엔딩을 검증합니다.
