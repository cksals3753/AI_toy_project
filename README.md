# 마지막 환승

React 19 + TypeScript + Vite 기반 **2D 탑다운 탐색 + 비주얼 노벨 대화** 생존 게임입니다. 신도림역을 모티브로 한 가상 구조이며 실제 대피 안내가 아닙니다. 첫 구간부터 챕터 3 신도림역 탈출까지 플레이할 수 있습니다. 외부 이미지·AI API·로그인·백엔드는 필요하지 않습니다.

## 실행

Node.js 22.12 이상을 사용하세요.

```sh
npm ci
npm run dev
```

```sh
npm run build   # TypeScript 검사 + 프로덕션 빌드
npm run lint
npm test       # 진행·저장·충돌·구역 접근성 검사
npm run preview
```

PC는 WASD / 방향키로 이동하고 가까운 사물·인물·문에서 E 또는 상호작용 버튼을 누릅니다. 모바일은 왼쪽 가상 조이스틱과 오른쪽 상호작용 버튼을 사용합니다. 휴대폰은 단톡방, 소지품은 전체 단서 노트를 엽니다. 대화·휴대폰·메뉴·미니게임 중에는 탐색이 멈춥니다. 대화는 Enter·Space 또는 버튼으로 넘길 수 있습니다.

## 구현한 진행

1. **첫 구간**: 감지 패널·안내도·물품함을 조사하고, 오반장과 직접 대화하거나 휴대폰으로 질문합니다. 경로 선택과 정비문 암호로 성공·부상·실패가 나뉩니다.
2. **대합실 전환**: 첫 구간 성공 결과에서 ‘대합실로 이동’을 누르거나, 결과창을 닫고 열린 서쪽 문에 상호작용합니다. 정비문 너머가 대합실로 이어지며 합선과 차단문으로 돌아갈 수 없는 이유를 대화로 설명합니다. 기존 성공 저장도 그대로 이어집니다.
3. **챕터 2 ‘불 꺼진 대합실’**: 네 인물의 상충하는 메시지, 안내도·점검창·개찰구 안내문·데스크 조사, 단서에 따른 추가 질문 3개를 제공합니다. 정체를 정답으로 표시하지 않습니다.
4. **직원 통로 분기**: 경고와 함께 내려오는 방화문을 피합니다. 시작 후 표시점이 녹색 구간(34–66%)에 들어오면 버튼을 누르는 5초 회피 게임입니다. 성공은 무피해, 실패는 체력 20 감소 후 대합실 복귀입니다. 사건 완료 상태는 저장되므로 반복 피해가 없습니다. 새로고침 중 사건은 시작 대기 상태로 재개합니다. 브라우저가 비활성화되면 타이머도 멈춥니다.
5. **전기실**: 안내 데스크의 열쇠가 필요합니다. 열쇠가 없으면 보관 장소 힌트를 줍니다. 별도 구역에 입장해 배전반을 조사합니다.
6. **예비 전원**: 조명·개찰구·방송 중 최대 두 개를 자유롭게 전환합니다. 초과 연결은 거부하며 켜진 장치를 먼저 끄도록 안내합니다. 방송은 사고 녹음 단서를 남기고, 꺼도 기록이 유지됩니다. 휴대폰 배터리와 전기실 예비 회로는 별도입니다.
7. **개찰구 통과**: 전원을 켜지 않으면 잠금 안내, 개찰구만 켜면 시야 확보 힌트를 줍니다. 조명과 개찰구를 모두 켜고 개찰구에 상호작용하면 계단 앞 구역으로 이동합니다.
8. **챕터 2 종료**: “지금 발소리, 몇 명 거예요?”라는 메시지 뒤, 멈춘 플레이어와 한 번 더 울린 발소리를 문장·시각 효과로 연출합니다. 대화를 마치면 완료와 저장을 처리합니다. 완료 후 새로고침으로 종료 대화를 반복하지 않습니다. 챕터 3은 아래 절차로 이어집니다.

## 에셋과 애니메이션

외부 에셋 대신 프로젝트 전용으로 작성한 벡터 아트를 사용합니다.

- `public/art/survivors.svg`: 6명 × 4방향 × 4프레임 스프라이트. 플레이어 방향 전환·걷기·정지 호흡.
- `public/art/station-atlas.svg`: 바닥·벤치·기둥·패널·안내도·물품함·데스크·배전반·차단문 타일.
- `src/components/Portrait.tsx`: 인물별 의상·헤어·모자·안경을 구분한 초상화, 등장 및 눈 깜빡임.
- 환경: 비상등 점멸, 회전하는 환풍기, 전원 ON/OFF, 조명 복구 시야 변화, 개찰구 개방, 구역 전환 페이드, 방화문 하강, 발소리 잔향 효과.

에셋 규격은 `public/art/README.md`에 있습니다. SVG/PNG 스프라이트로 교체할 수 있고 로딩 전에도 대체 도형으로 플레이할 수 있습니다. `prefers-reduced-motion`에서는 장식 애니메이션을 줄이며 회피 게임의 조작에 필요한 표시점은 유지합니다. 사운드는 사용하지 않습니다.

## 상태와 저장

`localStorage`의 기존 `last-transfer-save-v1` 키를 유지합니다. 저장에는 현재 구역·좌표·체력·배터리·아이템·전체 단서·질문·메시지·진행 단계·직원 통로 사건·전원 조합·종료 단계·대화 줄 위치가 포함됩니다.

과거 저장에 새 필드가 없으면 첫 구역과 기본 챕터 2 상태를 보충합니다. 유효하지 않은 좌표는 현재 구역 시작 위치로 복구합니다. 열쇠·단서·질문 획득과 위험 해결은 reducer에서 중복을 차단합니다. 다른 구역에서 늦게 도착한 위치 콜백도 무시합니다. 저장소가 차단되면 화면에 저장 실패를 알립니다. 같은 브라우저·주소에서 이어하며 새 게임은 확인 후 전체 회차를 초기화합니다.

첫 구간의 배터리는 패널 조사 8%, 물품함 5%, 암호 오답 10%에만 사용합니다. 챕터 2의 조사와 질문·예비 전원은 휴대폰 배터리를 소모하지 않습니다.

## 연결 구조

```text
키보드 / 조이스틱
  → Exploration.requestAnimationFrame
  → world.movePlayer (현재 구역의 충돌 + 정규화된 이동)
  → renderWorld (타일·방향 스프라이트·카메라·조명)

근접 E / 버튼 → nearestEntity → App.onInteract → engine.reducer
  → 단서·열쇠·사건·구역·전원·대화·완료 상태
  → React 대화 / 휴대폰 / 회피 / 배전반 / 결과 UI
  → Canvas 구역·전원·문 상태 반영

paused → 이동·상호작용 입력 정지
onPosition → 구역을 포함한 위치 갱신 → localStorage
```

- `src/game/data.ts`, `chapter2.ts`: 사건·대사·단서·질문·전원 장치 데이터.
- `src/game/engine.ts`: 판정, 자원, 구역 전환, 사건 단발 처리, 저장 마이그레이션.
- `src/game/world.ts`: 구역별 배치·충돌·근접 판정. 모든 상호작용 지점의 접근성을 테스트합니다.
- `src/game/renderWorld.ts`: 에셋 로드, Canvas 화면과 환경·걷기 애니메이션.
- `src/game/dialogue.ts`: 스크립트 대화 제공자. AI 교체 지점이며 판정 변경 권한은 없습니다.
- `src/components/Exploration.tsx`: 입력·프레임 루프·카메라·저장 위치 콜백.
- `src/components/DodgeGame.tsx`: 회피 타이밍 입력. 최종 피해와 사건 완료는 엔진이 처리합니다.
- `src/App.tsx`: Canvas와 React UI 연결. 대화 내용·진행 위치는 엔진 상태로 저장합니다.

## 브라우저 플레이 검증

프로젝트 의존성 외 추가 npm 패키지를 설치하지 않는 CDP 검증 스크립트를 제공합니다. Node.js의 WebSocket과 로컬 Chrome을 사용합니다.

```sh
npm run test:browser
# macOS 이외 또는 다른 Chrome 위치:
CHROME_PATH=/path/to/chrome npm run test:browser
```

임시 Vite(5175 포트)와 헤드리스 Chrome(9223 포트)을 시작해 검증 후 종료합니다. 테스트 전용 임시 브라우저 프로필을 사용하므로 실제 플레이 저장은 건드리지 않습니다. 스크린샷 경로를 마지막에 출력합니다. 로컬 포트·프로세스 실행을 허용하는 환경이 필요합니다.

실제 키보드로 첫 방을 탐색해 클리어한 뒤, 챕터 2 조사·질문·열쇠 잠금·직원 통로 실패 복귀·중복 피해 방지·전원 세 조합·방송 보존·개찰구 조건·모바일 조이스틱·종료 중 새로고침·완료 이어하기를 확인합니다. 별도 엔진 테스트에서는 위험 성공 경로와 과거 저장 복구도 검증합니다.

## 챕터 3 ‘누군가 있는 승강장’

챕터 2 완료창의 ‘승강장으로 이동’을 누르거나 완료창을 닫고 위쪽 계단에 상호작용하면 시작합니다. 과거 챕터 2 완료 저장도 그대로 이어집니다. 계단의 기존 발소리 연출과 완료 대화는 유지하며, 완료 후 직접 움직여 내려갈 수 있습니다.

승강장 위쪽의 **A-17 / △-1**, 아래쪽의 **B-04 / ◇-2**는 실제 운행 정보와 관계없는 가상 비상 운행 차량입니다. 차량 번호·선로 표식·열린 문·조명이 그래픽으로 구분됩니다. 안전 난간과 차량 충돌 영역으로 선로에 내려가는 조작은 제공하지 않습니다.

플레이 확인 순서:

1. 왼쪽 기둥 뒤 다친 생존자를 발견하고 대화합니다. 단톡방 네 명과 별개인 현장 인물입니다.
2. 부축하면 부스 옆 의자에서 동행을 기다립니다. 위치만 알려주면 먼저 조사할 수 있고, 나중에 다시 찾아 동행을 제안하거나 구조 대기 의사를 확인할 수 있습니다. 체력·아이템을 요구하지 않습니다.
3. A-17과 B-04를 조사합니다. A-17은 불이 켜졌지만 운행 중지입니다. 내부로 들어가 선두 안내를 확인하고 아래쪽 출입문으로 돌아올 수 있습니다. 이 사건의 단톡방 해명은 한 번만 발생합니다.
4. 오른쪽 비상 부스에서 오늘의 운행 기록, 왼쪽 아래 안전 난간에서 선로 표식과 붉은 신호를 확인합니다. 관련 질문 세 개가 열립니다.
5. 오른쪽 승인 장치에서 수집한 차량 번호와 선로 표식을 대조합니다. 단서 노트를 장치 안에서 펼칠 수 있습니다. 오답은 불일치 항목을 알리고 무제한 재시도합니다.
6. 정답 승인 → 출발 요청 → 약 1.4초 신호 전환 → 녹색 신호 후 B-04 비상 호출로 문을 엽니다. 신호 전환 중 새로고침하면 전환 대기를 재개합니다.
7. ‘B-04 선두 · 출발 확인’에서 최종 확인 후 탑승합니다. 생존자 동행 여부는 성공 조건이 아닙니다. 혼자 떠나면 생존자가 자신의 의사로 비상 부스 옆 의자에 남는다고 말하고 기록에 남습니다.
8. 객실과 멀어지는 신도림역 표지판 연출, 단톡방 마지막 두 메시지 이후 탈출 완료를 저장합니다. 다음 역은 **미확인**입니다. 챕터 4는 구현하지 않았습니다.

`src/game/chapter3.ts`는 사실·질문·대사·기본 상태, `chapter3Engine.ts`는 상태 전이, `src/components/Chapter3Panels.tsx`는 생존자 선택·승인·탑승 확인 UI를 담당합니다. 구역은 `platform`·`trainA`·`trainB`이며 기존 Canvas 렌더러와 에셋을 확장합니다. 생존자 전용 스프라이트 행과 부상 초상화를 추가했습니다. NPC 위치는 선택·탑승 시점에 이동하며 추적·공격 AI는 없습니다.

기존 저장 키와 버전은 유지하고 새 `chapter3` 필드에 기본값을 보충합니다. NPC 선택, A-17 해명, 승인·신호·문, 최종 탑승·동행·탈출, 대화 줄 위치를 저장합니다. 필수 조사와 재확인·승인 재시도에는 자원이 들지 않습니다. 종료 대화 중에도 이어하며 완료 후 자동으로 종료 대화를 반복하지 않습니다.

`npm test`에는 NPC 두 선택과 후속 초대·대기, A-17 왕복, 질문 해금, 오답 재시도, 승인·신호·문 선후 조건, 동행별 탈출, 저장 복구 및 새 구역 접근성 검증을 추가했습니다. `npm run test:browser`는 첫 방부터 챕터 3까지 실제 키보드 이동으로 연결해 검증하고 모바일 화면·중간 새로고침·초대/대기 분기도 확인합니다. 실제 모바일 기기 성능과 사운드는 별도 작업입니다.
