# 마지막 환승

React 19 + TypeScript + Vite 기반 **챕터 1~6 1인칭 3D + 비주얼 노벨 대화** 생존 게임입니다. 신도림역을 모티브로 한 가상 구조이며 실제 대피 안내가 아닙니다. 첫 구간부터 챕터 6 지상 대피소 도착과 에피소드 1 완료까지 플레이할 수 있습니다. 에셋은 프로젝트에서 제공하며 기본 플레이에 외부 AI API·로그인이 필요하지 않습니다. 챕터 2에는 선택적으로 서버 기반 AI 자유 대화를 연결할 수 있습니다.

## 챕터 1~2 생존 위협

첫 방의 봉쇄문 충격과 오반장 경고 이후, 대합실에서 감염자 한 명을 피해 조사합니다. 전투와 상시 제한 시간은 없으며 전기실은 안전 구역입니다. 대화·메뉴·퍼즐·포커스 이탈·탐색 복귀 대기 중 위협도 정지합니다. 붙잡히면 단서와 자원을 잃지 않고 안전 체크포인트에서 재시도합니다. [행동·저장·플레이 순서와 검증 방법](docs/chapter1-2-threat.md)을 참고하세요.

## 프론트 코드 작성 방식

- 함수와 React 컴포넌트는 `const` 화살표 함수로 작성합니다. 선언 전 호출에 의존하지 않도록 초기화 순서를 확인합니다.
- Tailwind CSS 4와 Vite 플러그인을 사용합니다. 기존 화면을 보존하기 위해 Preflight는 적용하지 않으며, `src/index.css`는 base, `src/App.css`는 components 레이어를 사용합니다. Tailwind 소스 탐색 범위는 `src/`입니다.
- 공통 버튼은 `src/components/ui/Button.tsx`, 단서와 결과 목록은 `src/components/ui/Records.tsx`를 재사용합니다. 챕터 3~6의 기본/텍스트 버튼에 적용했으며, 에피소드 결과 화면은 `EpisodeResult.tsx`로 분리했습니다.
- 새로운 공통 UI는 Tailwind 유틸리티로 작성하고, 탐색·3D·입력·판정 코드는 표현 컴포넌트와 분리합니다. 기존 전용 CSS는 필요한 범위에서 점진적으로 이전합니다.

## 지인 테스트 배포

Spring·API 키 없이 `npm run build:playtest`로 정적 테스트 빌드를 생성하고 `npm run preview`로 확인합니다. AI는 빌드에서 비활성으로 고정됩니다. Vercel 설정·로그인/저장소 연결 절차·저장 제약은 [배포 안내](docs/playtest-deployment.md)를 참조하세요. 실제 외부 배포는 아직 수행하지 않았습니다. `npm run test:browser:production`은 개발 서버가 아닌 프로덕션 미리보기에서 챕터 1~6을 검증합니다.

PC는 WASD / 방향키로 이동하고 가까운 사물·인물·문에서 E 또는 상호작용 버튼을 누릅니다. 모바일은 왼쪽 가상 조이스틱과 오른쪽 상호작용 버튼을 사용합니다. PC에서 Tab은 휴대폰 단톡방, 물리 I키는 소지품·단서를 열고 닫습니다. 두 메뉴 사이에서도 해당 키로 바로 전환하며 Esc로 닫습니다. 소지품은 기존 전체 단서 노트를 제공합니다. 대화·휴대폰·메뉴·미니게임 중에는 탐색이 멈춥니다. 대화는 Enter·Space 또는 버튼으로 넘길 수 있습니다.

## 챕터 1~6 1인칭 3D 탐색

챕터 1~6의 탐색은 브라우저 가용 화면(100dvh)을 채웁니다. 브라우저 전체화면 API는 HUD의 ⛶ 버튼으로만 선택적으로 사용합니다. 로고·페이지 헤더는 시작 화면에서 보이고, 플레이 중에는 작은 챕터·체력·배터리 HUD와 접을 수 있는 목표를 표시합니다. 휴대폰·소지품은 아이콘/단축키와 새 기록 배지를 유지합니다. ? 버튼에서 화면·조작 설정, 조작 안내와 저장 초기화 확인을 열 수 있습니다.

새 게임의 첫 안내에서 조작을 설명하며 이후 복귀 안내는 하단의 **클릭하여 탐색 계속** 문구만 표시합니다. HUD 버튼 클릭을 복귀 입력으로 사용하지 않습니다. 새 게임에서 첫 대화를 마친 뒤 탐색이 재개됩니다. 브라우저가 마우스 잠금을 허용하지 않으면 **화면을 클릭하면 탐색을 계속합니다** 안내에 따라 게임 화면을 한 번 클릭합니다. PC는 WASD(방향키 지원) 이동·마우스 시점 회전·중앙 조준점으로 대상 선택·E 조사입니다. 한/영 입력 상태와 관계없이 물리 E키를 사용합니다. **Tab으로 휴대폰, I로 소지품·단서를 바로 열 수 있습니다.** 같은 키로 닫거나 다른 메뉴 키로 전환합니다. 마우스로 Esc 해제 후 기존 버튼을 클릭하는 방식도 유지합니다. 첫 방의 짧은 사물 조사·아이템 획득·재확인은 비차단 현장 기록으로 표시해 이동과 시점을 유지합니다. 대화·메뉴·퍼즐은 조작을 멈추고 커서를 해제하며 마지막 대화·닫기·제출 입력에서 남은 UI가 없을 때 한 번만 잠금 복귀를 요청합니다. 거부되면 자동 재시도하지 않으며 게임 화면 클릭 한 번으로 복귀합니다. 이 복귀 클릭으로 조사나 이동을 함께 실행하지 않습니다. Esc로 직접 해제한 경우에도 자동으로 다시 잠그지 않습니다. 모바일은 pointer lock 없이 화면 좌하단 1/4에서 터치·끌기로 동적 조이스틱 이동·화면 오른쪽 드래그 시점·상호작용 버튼을 사용하며 UI 종료 후 바로 터치 탐색으로 돌아갑니다. UI 전환 시 누른 키·조이스틱·드래그를 비우고, 입력창과 contenteditable에서는 게임 키를 실행하지 않습니다. 메뉴 키는 게임 화면·조작 버튼 또는 해당 메뉴 안에 포커스가 있을 때만 처리합니다. 입력창·textarea·select·contenteditable에서는 단축키를 실행하지 않으며 입력 중 Tab/Shift+Tab은 포커스 이동을 유지합니다. 대화·퍼즐·전환 중에는 메뉴를 새로 열지 않고, 키를 길게 눌러도 반복 전환하지 않습니다. PC 버튼에만 단축키를 표시하고 모바일에는 터치 안내를 표시합니다.

Three.js 탐색기는 챕터 1~6의 공간에서 공통으로 지연 로드합니다. 입력·이동·시점·정리는 `FirstPersonExploration.tsx`를 공유합니다. 기존 `world.ts` 좌표·사각 충돌과 `App.tsx → engine.ts` 상호작용·아이템·퍼즐·저장을 재사용합니다. 승강장과 열차 A 조사 객실, 챕터 4 중앙·후방·선두 객실, 문래역 승강장·안내 부스·확인 대기 구역, 정비 통로 분기실·복구 구역·지상 대피소도 3D로 이어집니다. 에피소드 1 결과는 기존 React UI에서 확인합니다. 별도 게임 저장을 만들지 않으며 이전 첫 방 저장도 같은 위치에서 이어집니다. 새 3D 저장은 현재 구역의 렌더러 좌표와 yaw/pitch 방향을 저장하고 검증해 복원합니다. 과거 챕터 2~6의 2D 저장은 진행 상태를 유지하면서 해당 구역의 안전 시작점에서 3D 탐색을 시작합니다. 이전 첫 방 저장은 유효한 기존 충돌 좌표를 유지합니다.

WebGL2 사용 불가·컨텍스트 손실 시 같은 상태로 2D 탐색으로 전환합니다. 개발 시 `VITE_FIRST_ROOM_3D=false npm run dev`로 기존 챕터 1~6의 2D 렌더러를 확인할 수 있습니다. 환경변수 이름은 호환을 위해 유지합니다. WebGL2 오류 시 모든 챕터에서 같은 상태의 2D 대체 렌더러로 계속할 수 있습니다.

첫 방의 시설은 안내도·감지 계기·물품함 라벨로 표현하며 조작 설명은 HUD에 표시합니다. 가까이 다가가 조준하면 `E 대상 이름 조사`가 나타납니다. 벤치 배치와 소수의 가방·바닥 안내문·끌린 자국·먼지·벽 손상은 장식이며 추가 조사 대상이나 새 사건을 만들지 않습니다. 카메라 높이 1.50m·기본 세로 시야각 64도(화면비 보정)와 국소 조명으로 구도를 조정했으며 캐릭터·충돌·저장·퍼즐은 유지합니다. [같은 시점의 환경 전후 비교](docs/visual-review/environment.md)를 확인할 수 있습니다.

AI 비활성 상태의 첫 방만 검사할 때는 Java 없이 다음 명령을 사용할 수 있습니다.

```sh
npm run test:browser:first
FIRST_PERSON_CHECK=chapter2 npm run test:browser:first
FIRST_PERSON_CHECK=resume npm run test:browser:first
FIRST_PERSON_CHECK=shortcuts npm run test:browser:first
VISUAL_LABEL=environment-after FIRST_PERSON_CHECK=visual npm run test:browser:first
```

챕터 2의 상세 플레이 순서·저장 호환·시설 상태·스크린샷·검증 범위는 [챕터 2 3D 기록](docs/chapter2-3d/README.md)을 참조하세요. 필수 에셋은 로딩 중 조작을 차단하고, 8초 안에 준비되지 않으면 재시도 또는 같은 진행의 2D 복귀를 제공합니다. 벤치 등 보조 에셋은 기본 형상을 남기므로 에셋 실패가 이동 경로를 숨기지 않습니다. 구역을 나가면 이전 WebGL 자원과 입력 이벤트를 정리합니다.

## 플레이 편의 기능

- 저장된 진행이 있으면 시작 화면에서 챕터·구역·체력·단서·저장 시각을 확인한 뒤 **이어하기**를 누릅니다. 새 게임은 별도 확인 후 초기화하며 취소하면 기존 저장을 유지합니다.
- 화면 위 **다음 목표**가 진행에 따라 갱신됩니다. 조사 전 정답 차량·문 번호를 목표에 표시하지 않습니다.
- 소지품의 현장 기록을 장소별로 묶었습니다. `✦ 새 단서`·`✦ 새 메시지`와 `✓ 확인함`으로 색상 없이도 구분합니다. 소지품·단톡방을 닫으면 당시 기록을 확인 처리하며 읽음 상태도 저장합니다. 과거 저장은 읽음 기본값을 보충합니다.
- 조사 완료 사물 근처에는 `✓ 조사 완료`와 **단서 재확인**이 표시됩니다. 대화·휴대폰·퍼즐·구역 전환 뒤에는 방향키를 놓고 다시 눌러 이동합니다. 터치 조작은 대화·메뉴 중 숨기며 종료 후 복구합니다. 첫 방의 짧은 조사 기록은 탐색을 차단하지 않습니다.
- 챕터가 바뀔 때 제목을 약 1초 표시합니다. 현재 챕터를 불러오는 것만으로 전환 연출이나 일회성 사건을 재실행하지 않습니다. 동작 줄이기 설정에서는 애니메이션을 생략합니다.

## 구현한 진행

1. **첫 구간**: 감지 패널·안내도·물품함을 조사하고, 오반장과 직접 대화하거나 휴대폰으로 질문합니다. 경로 선택과 정비문 암호로 성공·부상·실패가 나뉩니다.
2. **대합실 전환**: 첫 구간 성공 결과에서 ‘대합실로 이동’을 누르거나, 결과창을 닫고 열린 서쪽 문에 상호작용합니다. 정비문 너머가 대합실로 이어지며 합선과 차단문으로 돌아갈 수 없는 이유를 대화로 설명합니다. 기존 성공 저장도 그대로 이어집니다.
3. **챕터 2 ‘불 꺼진 대합실’**: 네 인물의 상충하는 메시지, 안내도·점검창·개찰구 안내문·데스크 조사, 단서에 따른 추가 질문 3개를 제공합니다. 정체를 정답으로 표시하지 않습니다.
4. **직원 통로 분기**: 경고와 함께 내려오는 방화문을 피합니다. 시작 후 표시점이 녹색 구간(34–66%)에 들어오면 버튼을 누르는 5초 회피 게임입니다. 성공은 무피해, 실패는 체력 20 감소 후 대합실 복귀입니다. 사건 완료 상태는 저장되므로 반복 피해가 없습니다. 새로고침 중 사건은 시작 대기 상태로 재개합니다. 브라우저가 비활성화되면 타이머도 멈춥니다.
5. **전기실**: IS-02 빗장 해제와 셔터 올림·걸쇠 고정을 각각 완료해야 합니다. 안내 데스크의 열쇠가 필요합니다. 열쇠가 없으면 보관 장소 힌트를 줍니다. 별도 구역에 입장해 배전반을 조사합니다.
6. **예비 전원**: 조명·개찰구·방송 중 최대 두 개를 자유롭게 전환합니다. 초과 연결은 거부하며 켜진 장치를 먼저 끄도록 안내합니다. 방송은 사고 녹음 단서를 남기고, 꺼도 기록이 유지됩니다. 휴대폰 배터리와 전기실 예비 회로는 별도입니다.
7. **개찰구 통과**: 전원을 켜지 않으면 잠금 안내, 개찰구만 켜면 시야 확보 힌트를 줍니다. 조명과 개찰구를 모두 켜고 개찰구에 상호작용하면 계단 앞 구역으로 이동합니다.
8. **챕터 2 종료**: “지금 발소리, 몇 명 거예요?”라는 메시지 뒤, 멈춘 플레이어와 한 번 더 울린 발소리를 문장·시각 효과로 연출합니다. 대화를 마치면 완료와 저장을 처리합니다. 완료 후 새로고침으로 종료 대화를 반복하지 않습니다. 챕터 3은 아래 절차로 이어집니다.

## 에셋과 애니메이션

## 상태와 저장

`localStorage`의 기존 `last-transfer-save-v1` 키를 유지합니다. 저장에는 현재 구역·좌표·체력·배터리·아이템·전체 단서·질문·메시지·진행 단계·직원 통로 사건·전원 조합·종료 단계·대화 줄 위치가 포함됩니다.

과거 저장에 새 필드가 없으면 첫 구역과 기본 챕터 2 상태를 보충합니다. 유효하지 않은 좌표는 현재 구역 시작 위치로 복구합니다. 열쇠·단서·질문 획득과 위험 해결은 reducer에서 중복을 차단합니다. 다른 구역에서 늦게 도착한 위치 콜백도 무시합니다. 저장소가 차단되면 화면에 저장 실패를 알립니다. 같은 브라우저·주소에서 이어하며 새 게임은 확인 후 전체 회차를 초기화합니다.

첫 구간의 배터리는 패널 조사 8%, 물품함 5%, 암호 오답 10%에만 사용합니다. 챕터 2의 조사와 질문·예비 전원은 휴대폰 배터리를 소모하지 않습니다.

## 챕터 3 ‘누군가 있는 승강장’

챕터 2 완료창의 ‘승강장으로 이동’을 누르거나 완료창을 닫고 위쪽 계단에 상호작용하면 시작합니다. 과거 챕터 2 완료 저장도 그대로 이어집니다. 계단의 기존 발소리 연출과 완료 대화는 유지하며, 완료 후 직접 움직여 내려갈 수 있습니다.

승강장 위쪽의 **A-17 / △-1**, 아래쪽의 **B-04 / ◇-2**는 실제 운행 정보와 관계없는 가상 비상 운행 차량입니다. 차량 번호·선로 표식·열린 문·조명이 그래픽으로 구분됩니다. 안전 난간과 차량 충돌 영역으로 선로에 내려가는 조작은 제공하지 않습니다.

플레이 확인 순서:

1. 왼쪽 기둥 뒤 다친 생존자를 발견하고 대화합니다. 단톡방 네 명과 별개인 현장 인물입니다.
2. 부축하면 부스 옆 의자에서 동행을 기다립니다. 위치만 알려주면 먼저 조사할 수 있고, 나중에 다시 찾아 동행을 제안하거나 구조 대기 의사를 확인할 수 있습니다. 체력·아이템을 요구하지 않습니다.
3. A-17과 B-04를 조사합니다. A-17은 불이 켜졌지만 운행 중지입니다. 내부로 들어가 선두 안내를 확인하고 아래쪽 출입문으로 돌아올 수 있습니다. 이 사건의 단톡방 해명은 한 번만 발생합니다.
4. 오른쪽 비상 부스에서 오늘의 운행 기록, 왼쪽 아래 안전 난간에서 선로 표식과 붉은 신호를 확인합니다. 관련 질문 세 개가 열립니다.
5. 오른쪽 승인 장치에서 수집한 차량 번호와 선로 표식을 대조합니다. 단서 노트를 장치 안에서 펼칠 수 있습니다. 오답은 불일치 항목을 알리고 무제한 재시도합니다.
6. 정답 승인 → 출발 요청 → 약 1.4초 신호 전환 → 녹색 신호 후 B-04 비상 호출로 문을 엽니다. 신호 전환 중 새로고침하면 전환 대기를 재개합니다.
7. ‘B-04 선두 · 출발 확인’에서 최종 확인 후 탑승합니다. 생존자 동행 여부는 성공 조건이 아닙니다. 혼자 떠나면 생존자가 자신의 의사로 비상 부스 옆 의자에 남는다고 말하고 기록에 남습니다.
8. 객실과 멀어지는 신도림역 표지판 연출, 단톡방 마지막 두 메시지 이후 탈출 완료를 저장합니다. 챕터 3 종료 시 다음 역은 **미확인**이며, 챕터 4에서 비상 정차 지점을 확인합니다.

`src/game/chapter3.ts`는 사실·질문·대사·기본 상태, `chapter3Engine.ts`는 상태 전이, `src/components/Chapter3Panels.tsx`는 생존자 선택·승인·탑승 확인 UI를 담당합니다. 구역은 `platform`·`trainA`·`trainB`이며 기존 Canvas 렌더러와 에셋을 확장합니다. 생존자 전용 스프라이트 행과 부상 초상화를 추가했습니다. NPC 위치는 선택·탑승 시점에 이동하며 추적·공격 AI는 없습니다.

기존 저장 키와 버전은 유지하고 새 `chapter3` 필드에 기본값을 보충합니다. NPC 선택, A-17 해명, 승인·신호·문, 최종 탑승·동행·탈출, 대화 줄 위치를 저장합니다. 필수 조사와 재확인·승인 재시도에는 자원이 들지 않습니다. 종료 대화 중에도 이어하며 완료 후 자동으로 종료 대화를 반복하지 않습니다.

## 챕터 4 ‘정차하지 않는 열차’

챕터 3의 열차 탑승·신도림역 탈출 완료 후 시작합니다. 완료창 또는 객실 위쪽의 ‘챕터 4 시작’ 버튼을 사용합니다. 기존 챕터 3 완료 저장도 초기화 없이 이어갈 수 있습니다. `episode.next`에 이미 설정된 **문래역**을 우선하며, 철도 장치·이동·역 구조는 모두 게임용 가상 설정입니다.

### 플레이 확인 순서

1. 시작 대화에서 객실 인원을 확인합니다. 동행 시 나와 다친 생존자 두 명, 비동행 시 나 혼자입니다. 단톡방 네 인물은 원격 연결이며 실제 객실 인원에 포함하지 않습니다. 진동의 원인은 좌석 아래 유실 휴대폰입니다.
2. 중앙 객실의 좌석 아래 휴대폰과 위쪽 노선 표시기를 조사합니다. 화면 확인은 안전하며 연결 요청을 실행하지 않습니다. 표시기는 비상 회송·정차 요청 없음 상태입니다. 조사에 따라 휴대폰 질문이 열리고 최근 메시지 시각과 전송 기록을 비교할 수 있습니다.
3. 오른쪽 문으로 후방 객실에 이동합니다. 위쪽 설명서와 통신 장치함을 조사하고, 단서 노트를 펼쳐 R-01 / CAB-R01, X-09 / EXT-X09, P-02 / PWR-P02를 대조합니다. 장치함 조사 시 실제로 전원 차단 권유가 도착한 뒤에만 그 발언을 묻는 질문이 나타납니다.
4. 잘못 끊은 연결은 같은 장치함에서 즉시 복구합니다. 전원이 꺼져도 비상등·문자 표식·장치함 상호작용이 유지됩니다. 전원 OFF는 선두 패널 꺼짐, 중계기 OFF는 연결 오류로 나타납니다. 체력·배터리·아이템 소모나 재시도 제한이 없습니다.
5. 외부 송신 연결 분리 시 수신 중단 대화가 나오고 다음 대화 버튼으로 독립 연결 복구가 이어집니다. 실제 네트워크는 차단하지 않습니다. 분리 사실을 알리기 전에 오반장이 반응하며, 일회성 대사와 의심 기록은 저장됩니다. 인물 정체가 확정되는 연출은 없습니다.
6. 중앙 객실로 돌아와 왼쪽 문으로 선두 연결 구역에 이동합니다. 운전실은 잠겨 있으며 들어갈 수 없습니다. 외부 패널을 조사하고 정차 요청 신호 동기화를 시작합니다.
7. 표시가 경계선 28–72% 안에 있을 때 클릭·터치 또는 버튼에 초점을 두고 Enter/Space로 한 번 누릅니다. 신호는 6초 주기로 반복하며 시간제한은 없습니다. 실패 시 재시도하고, 2회 실패 후 10초 주기의 느린 신호 보조를 켤 수 있습니다. 탐색 입력은 차단합니다. 진행 중 저장은 활성 상태·실패 횟수·보조 여부를 유지하며, 이어하기 시 표시점은 처음부터 시작합니다.
8. 성공 대화를 마치면 열차가 감속·정차하고 노선 표시기가 ‘문래역 — 비상 정차’로 바뀝니다. 중앙 객실 출입문으로 이동하면 경고 메시지가 현장 확인보다 먼저 도착하고 같은 방향의 신발 여러 켤레를 보게 됩니다.
9. 역 진입 확인에서 보류하면 다시 조사할 수 있습니다. 승인하면 챕터 4 완료·도착을 저장합니다. 역 안 탐색은 챕터 5 범위로 남겨 둡니다.

## 챕터 5 ‘대답 없는 승강장’

목적지는 기존 `episode.next`와 챕터 4의 **문래역**을 유지합니다. 신규·기존 회차의 목적지를 나누지 않습니다. 챕터 4의 역 진입을 승인한 뒤 ‘챕터 5 · 대답 없는 승강장 시작’을 누릅니다. 이전 챕터 4 완료 저장은 새 상태 기본값을 보충해 이어갑니다.

휴대폰 프로필에서 **이전부터 사용하던 단톡방 표시 이름**을 확인합니다. 실제 이름은 필요하지 않으며 기본 이름 ‘한결’ 또는 공백 제거 후 1~16자의 게임용 이름을 사용합니다. 빈 값·공백만 있는 값·길이 초과는 거부합니다. 입력 중 초안도 저장하고, 확인 후 이름은 그 회차에서 고정합니다. 방송 자막과 등록 원본은 같은 값을 참조합니다. 이 확인은 새 정보를 전송하는 사건이 아닙니다. 로그인, 실제 기기 정보, 음성 입력·마이크 권한을 사용하지 않습니다.

### 공간과 공통 조사

플레이어가 직접 이동하는 세 구역은 **문래역 승강장 / 안내 부스 / 확인 대기 구역**입니다. 기존 WASD·방향키·가상 조이스틱·근접 E·상호작용 버튼을 사용합니다. 방송은 별도 화자와 텍스트 자막으로 나타나며, 승강장 방송 장치와 단서 노트에서 다시 확인할 수 있습니다. 사람 대신 놓인 신발과 방향 표식은 캔버스에 표시합니다.

승강장에서 전광판의 ‘응답 감지 시 확인 구역 차단문 작동’ 경고와 MIC-03을 조사합니다. 응답 패널에서도 선택 직전에 같은 경고를 다시 보여줍니다. 일반 이동·대화 넘기기·실제 소리는 응답으로 처리하지 않으며, ‘대답한다’ 버튼을 명시적으로 선택해야 합니다. 무응답도 명시적 선택으로 기록하며 실제 시간제한은 없습니다.

### 무응답 플레이 확인 순서

1. 프로필 확인 → 도입 방송과 기존 경고 확인 → 신발·전광판·감지기·점검창 조사.
2. MIC-03 선택 패널에서 ‘응답하지 않는다’를 선택합니다. 차단문은 작동하지 않습니다.
3. 오른쪽 안내 부스로 걸어가 방송 재생 기록·외부 자료 수신·등록 원본 수동 첨부를 조사합니다.
4. 등록 단말에서 열차 기록과 차량·발신 식별자·시각·표시 이름·등록 건을 대조합니다. 동일 시각의 다른 차량·다른 발신 장치 등록은 거부합니다. 정답은 고정 데이터로 관리합니다.
5. 대조 후 ‘미확인 등록 보류’로 외부 유도를 중단합니다. 이것만으로 정비 통로는 열리지 않습니다.
6. 승강장으로 돌아와 M-12 표식을 별도로 조사하고, D-02 정비 통로의 현장 통행 조건을 대조합니다.
7. 열린 문 앞에서 분기별 종료 방송을 확인합니다. 이동을 보류하거나 승인할 수 있습니다. 승인하면 챕터 5 완료와 통로 이동 승인 상태를 저장합니다.

### 응답 플레이 확인 순서

1. 같은 경고 조사 후 MIC-03에서 ‘경고를 확인했으며 대답한다’를 선택합니다.
2. 확인 대기 구역으로 이동하고 차단문이 닫힙니다. NPC 동행 시 함께 들어오며, 대신 응답하거나 퍼즐을 해결하지 않습니다. 신발·아이템은 자동으로 잃지 않습니다.
3. 내부 활성 등록 표시와 해제 안내를 직접 조사합니다. 내부 취소 장치에서 해당 등록을 취소하면 차단문이 열립니다. 오답은 재시도할 수 있습니다.
4. 아래 문으로 승강장에 복귀해 안내 부스의 세 증거를 조사·대조하고 ‘취소된 등록의 외부 유도 보류’를 처리합니다.
5. 이후 M-12 표식 조사 → 현장 통행 조건 대조 → 분기별 종료 방송 → 정비 통로 이동 승인으로 완료합니다.

## 챕터 2 AI 자유 대화

선택적 AI 대화 API는 Java 21 + Spring Boot 4.1.1의 `backend/`에서 실행합니다. 기존 Node AI 서버는 제거했습니다. 기본 게임은 서버나 키 없이도 진행됩니다. 실제 결제·호출 검증은 보류 중이며 자유 대화는 기본 비활성입니다. 키만 설정해도 켜지지 않습니다. 챕터 2 이외의 AI 자유 대화 확장은 계획이며 구현 완료가 아닙니다.

```sh
cp backend/.env.example backend/.env.server
# 현재는 AI_CHAT_ENABLED=false 유지 (키 없이 실행 가능)
npm run dev:server
# 다른 터미널
npm run dev
```

설치된 Temurin 21을 사용하며 Maven Wrapper가 빌드 도구를 준비합니다. Spring 서버 기본 주소는 `127.0.0.1:3001`, Vite는 `/api/chat`을 프록시합니다. 서버는 API만 제공하며 `dist` 정적 서빙은 하지 않습니다. `npm start`도 Spring 실행입니다.

키는 서버 환경변수 또는 Git에서 제외한 `backend/.env.server`에만 둡니다. 파일은 Java properties 형식으로 `export`나 따옴표 없이 작성합니다. 기존 루트 `.env.server`도 읽지만 backend 파일이 우선하고 OS 환경변수가 가장 우선합니다. `VITE_` 변수·브라우저·로그·커밋에 키를 넣지 마세요. 세부 환경변수와 직접 Maven/JAR 실행은 [백엔드 README](backend/README.md), 요청·응답·제한·오류 처리는 [API 계약](docs/ai-api-contract.md)에 있습니다.

판정·자원·해금·localStorage는 기존 게임 엔진이 담당합니다. AI는 선택한 인물의 허용된 지식과 공개된 증거로 대사만 생성합니다. 조사와 단톡방 공유를 구분하며 사용자 주장만으로 아이템이나 정답을 바꾸지 않습니다. 비공개 인물 설정은 `backend/src/main/resources/private/characters.json`에만 있습니다. 서버 연결 실패·키 미설정 상황에서도 선택형 질문과 필수 진행을 유지합니다.

```sh
npm run backend:test    # 단위·로컬 HTTP·모의 제공자 테스트
npm run backend:build   # 테스트 및 실행 JAR 패키징
npm test
npm run build
npm run lint
npm run format:check
npm run test:browser    # Spring 테스트 fixture + Vite + 로컬 Chrome
# 실제 키 없이 production 제공자의 비활성 UI 확인:
KEYLESS_CHAT_CHECK=1 npm run test:browser
```

브라우저 검증의 모의 제공자는 테스트 클래스에만 존재하며 배포 JAR에 포함하지 않습니다. 실제 OpenAI 키·유료 호출·모델 품질 검증은 이번 작업에서 수행하지 않습니다. 추후 명시적으로 재개할 때 서버 `AI_CHAT_ENABLED=true`와 프론트 `VITE_AI_CHAT_ENABLED=true`를 함께 설정하고 양쪽 개발 서버를 재시작하세요(프론트 실행 예: `VITE_AI_CHAT_ENABLED=true npm run dev`). 크레딧·사용 한도 부족이 확인되면 서버가 제공자 호출을 중단하며, 결제 문제 해결 후 서버를 재시작해야 해제됩니다. 일반 속도 제한은 이 영구 차단 대상이 아닙니다. 키 설정 후 [실제 연결 확인 절차](backend/README.md)를 따라 네 인물 응답, 공유 전후 지식, 실패·재시도, 자원 불변을 확인하세요. 세션·캐시·호출 제한은 단일 프로세스 메모리이며 재시작 시 초기화됩니다. 로그인·DB·전체 상태 서버 이전·외부 배포는 포함하지 않습니다.

## 챕터 6 ‘정비 통로’ · 에피소드 1 완결

챕터 5 이동 승인 완료 후 **챕터 6 · 정비 통로 진입** 버튼 또는 D-02 상호작용으로 시작합니다. 기존 완료 저장도 이어갈 수 있습니다. 체력·배터리·소지품·과거 기록·NPC 동행을 유지합니다. 과거 선택 단서는 필수 조건이 아니며 최종 판단 근거는 현장에서 다시 확보합니다. AI는 계속 기본 비활성이고 서버 없이 플레이할 수 있습니다.

동행 생존자는 두 경로 모두 함께 도착합니다. 비동행 생존자는 신도림역에서 마지막 확인한 위치만 기록하며 이후 구조를 단정하지 않습니다. 도움을 준 방식에 따라 진입·결과 대사를 구분합니다.

도착 확인대에서만 에피소드 완료를 확정합니다. 결과 화면에는 도착 당시의 경로·주요 선택·자원·동행·확인/미확인 사실·획득 단서 전문·실제 대화를 저장된 스냅샷으로 표시합니다. 기록 열람·새로고침·재조작으로 결과나 자원이 바뀌지 않습니다. 인물 정답표·점수·등급·보상은 없습니다. 대피소 보기 후 **저장된 결과 보기**로 다시 열 수 있습니다.

구현은 `src/game/chapter6.ts`, `chapter6Engine.ts`, `src/components/Chapter6Panels.tsx`와 기존 탐색·저장·렌더러를 사용합니다. 제작자 설정은 [챕터 6 제작자 문서](docs/chapter6-author.md)에 분리했습니다.

### 화면·조작 편안함

HUD **? → 화면·조작**에서 마우스 감도·터치 감도·세로 기준 FOV(55–80°)·이동 속도(60–100%)를 즉시 변경하고 기본값을 복원합니다. 설정 중 탐색과 위협은 정지합니다. 진행 저장과 별도의 `last-transfer-comfort-v1` 키에 저장하므로 새 게임으로 진행을 초기화해도 설정은 유지됩니다. 저장이 차단되어도 현재 플레이에는 적용됩니다.

기본 마우스 감도는 0.0025 → 0.0015 rad/CSS px, 터치는 0.006 → 0.003 rad/CSS px(짧은 변 390px 기준), 이동은 165 → 132 월드 단위/초입니다. 감염자의 이동도 같은 비율로 조절하며 감지·붙잡힘 시간은 변경하지 않습니다. 터치는 화면의 짧은 변 비율로 보정하고 회전량에 프레임 시간이나 DPR을 곱하지 않습니다. PC 하드웨어 DPI·OS 마우스 설정의 차이까지 보정하지는 않습니다.

카메라 흔들림·기울기·관성·자동 회전·이동 중 FOV 변경·모션 블러·가장자리 왜곡은 사용하지 않습니다. 기존 위아래 제한 ±1.1 rad(약 63°)와 중앙 조준점은 유지합니다. 세로 FOV 기본 64°는 유지하되 아주 좁거나 넓은 화면에서 가로 40–105° 범위를 적용합니다. 따라서 극단적인 화면비에서는 실제 세로 각도가 설정값과 달라집니다. 구역 로딩 후 240ms 페이드 동안 입력과 위협을 멈추고 안정된 위치에서 시작합니다.

[비교 방법·자동 검증과 제약](docs/comfort-review/README.md)을 참고하세요. 자동 수치 검증은 사람이 느끼는 멀미가 해결됐다는 의미가 아닙니다.

### 모바일 조작·모달 닫기

좌하단 1/4에서 터치를 시작하면 해당 위치에 이동 조이스틱이 나타나고, 손을 떼면 사라집니다. 처음 누른 위치에서는 이동하지 않으며 가장자리에서는 원이 잘리지 않도록 표시 중심만 보정합니다. 손가락을 영역 밖으로 끌어도 같은 pointerId의 이동이 유지되고 오른쪽 시점 드래그와 함께 사용할 수 있습니다. 좌상단은 이동 영역이 아닙니다. 취소·메뉴·포커스 이탈 시 입력을 초기화합니다. 3D와 2D 대체 화면은 같은 조이스틱을 사용합니다.

Esc로 닫을 수 있는 화면에는 하단 닫기 또는 기존 돌아가기 버튼이 있습니다. 닫기는 제출·이동 확정·아이템 획득과 별개입니다. 필수 선택/회피 화면에는 임의의 닫기를 추가하지 않았습니다. 메뉴/닫기 버튼은 이동 손가락을 누른 채 다른 손가락으로 탭하는 경우도 처리하며 취소·버튼 밖 해제를 무시하고 중복 click을 차단합니다.

[조작·모달 확인 기록](docs/controls-review.md)을 참고하세요. 이후 승인된 챕터 2 재구성을 구현했습니다. 중앙 침수 구간을 우회하며 기존 감염자를 관찰하고, IS-02에서 빗장 해제 → 셔터 올림·걸쇠 고정을 각각 한 번의 입력으로 수행합니다. E-01 첫 방문 후 안전 조건이 맞으면 동측 연결이 추가 침수되며, 서측·상단 건조 경로로 개찰구에 도달합니다. 조사 수집 개수·기존 사실·전원 두 회로 제한은 유지합니다.

각 셔터 단계는 약 0.9초이며 이동·메뉴·붙잡힘·포커스 이탈로 중단하면 마지막 확정 단계부터 재시도합니다. 설명창에서는 위협이 멈추고 현장 조작 중에는 움직입니다. 과거 전기실 진입/전원 진행 저장은 셔터 개방으로 호환하며, 침수 안의 저장 위치는 안내 후 안전 위치로 복구합니다. 도움말의 장면 밝기(85–125%)와 확인 샘플은 진행 저장과 별도로 보관합니다.

[수위별 동선·셔터 캡처·실제 플레이 및 검사](docs/chapter2-restructure/README.md), [당시 미구현 제안 기록](docs/chapter2-restructure-proposal.md)을 참고하세요. Spring 없이 `npm run build:playtest` 후 `PRODUCTION_CHECK=1 FIRST_PERSON_CHECK=restructure node scripts/verify-browser.mjs`로 프로덕션 3D 경로와 조작을, `FIRST_PERSON_CHECK=restructure-controls npm run test:browser:first`로 2D 대체 화면까지 검사합니다.

## 시설 식별과 조사 거리 개선

챕터 2 간판을 벽·출입구 위로 정리하고, 안내도 프레임·점검창 계기/그릴·데스크 서랍/열쇠·배전반 스위치·셔터 레일/손잡이를 구분했습니다. 안내·관찰은 전체 형태가 보이는 거리, 조작은 더 가까운 거리로 나누며 실제 조사 표면으로 판정합니다. 이동·충돌 경로를 좁히거나 FOV를 강제로 바꾸지 않습니다. [대표 거리 전후·스크린샷·브라우저 검증과 제약](docs/facility-review/README.md)을 참고하세요.

챕터 1·3–6도 시설별로 점검해 호출기·센서·등록/승인 단말·통신 랙·밸브·빗장·해치·확인대를 구분했습니다. 안내 시설은 전체 형태를 볼 수 있는 거리, 버튼·손잡이는 근접 거리로 따로 조정하며 문·NPC·휴대폰 등 자연스러운 대상은 유지합니다. [챕터별 수정/유지·거리 전후·동일 시점 캡처·검증](docs/episode-facilities/README.md)을 참고하세요.

시설 개선 후 최종 프로덕션 빌드에서 새 게임부터 엔딩까지 상태 주입·챕터 점프 없이 연속 완주했습니다. 생존자 동행 → 문래역 무응답 → S-01 수동 대피 경로이며, 저장·이어하기와 엔딩 재열람도 확인했습니다. 자동 입력 검증은 356초로 사람의 플레이 시간과 구분합니다. [실제 경로·검사 결과·남은 제약](docs/episode-facilities/continuous-final/README.md)을 참고하세요.
