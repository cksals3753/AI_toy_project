# A. 동적 조이스틱·모달 확인 기록

B의 침수·수동 셔터 재구성은 [미구현 제안서](chapter2-restructure-proposal.md)로 분리했다. 이 작업은 게임 판정·진행 저장 구조·기존 수위·감염자 규칙을 바꾸지 않는다.

## 재현과 원인 구분

| 확인 화면/조건                                                    | 수정 전 결과                                             | 조치                                                                                        |
| ----------------------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 챕터 4 신호 동기화, 일반 마우스 하단 취소                         | 정상 취소, 성공으로 처리되지 않음                        | 진행 규칙 유지. 공통 취소 버튼으로 재사용                                                   |
| 휴대폰 모달, 이동 손가락을 계속 누른 채 다른 손가락으로 하단 닫기 | 하단 탭 후 모달 유지, Esc로 닫힘을 실제 Chrome에서 재현  | 버튼 click만 기다리지 않고 보조 터치의 눌림/해제·버튼 내부 위치를 확인해 같은 닫기 실행     |
| 여러 공통/장별 모달                                               | Esc·상단 X만 있고 하단 닫기는 없거나, 진행 버튼만 있었음 | onClose가 있는 화면에 공통 하단 닫기 추가. 이미 하단 취소가 있으면 중복 없이 기존 버튼 유지 |
| 암호/승인/제어반에서 미입력·오답                                  | 제출 비활성 또는 오류 안내 후 유지되는 것이 정상         | 닫기와 제출 구분. 네 자리 입력 조건과 제어반 설정 저장 조건을 안내                          |
| 필수 NPC 도움 선택·이름 확인·직원 통로 회피                       | onClose가 없고 선택/행동이 필요함                        | Esc/임의 닫기를 추가하지 않음                                                               |

처음 제보된 특정 화면은 지목되지 않았으므로 모든 모달에서 같은 원인이 난다고 단정하지 않는다. 재현한 보조 손가락 문제는 HTML click이 발생하지 않는 입력 경로였으며, 정상 단일 클릭 취소의 reducer 오류는 확인되지 않았다. 모달 callback 참조 변화마다 포커스를 재설정하던 구조도 제목/화면 전환 시에만 초기화하도록 보완했다. 이 포커스 보완을 원래 제보의 확정 원인으로 보고하지 않는다.

검사 중 CDP touchEnd에 남아 있을 손가락을 넣어 이동 pointerup을 잘못 발생시킨 자동화 오류도 있었다. 실제 pointer 이벤트 로그로 구분하고 종료할 터치 ID를 지정하도록 검사 코드를 고쳤다. 로컬 Chrome에서 관측한 동작과 관련된 [Chromium 다중 터치 프로토콜 이슈](https://issues.chromium.org/issues/569778218)를 참고한다. 이 문제 때문에 실제 기기 동작을 에뮬레이션만으로 보증하지 않는다.

## 실제 변경

- `DynamicJoystick.tsx`를 두 렌더러가 공유한다. 탐색 화면 좌하단 1/4만 시작 영역이다. 시작 접촉은 중립이며 5px 미만 흔들림은 무시한다. 최대 변위 33px, 대각선 벡터는 정규화한다. 시각 원 중심은 반경 여유를 두고 보정하지만 입력 원점은 실제 시작 터치를 유지한다.
- pointer capture로 영역 밖에서도 같은 손가락을 추적한다. 다른 손가락은 이동을 인계받지 않는다. 해제/취소/blur/메뉴/구역 언마운트는 이동을 비우고 원을 숨긴다. 버튼·대화창은 별도 UI 계층이며 이동 영역으로 처리하지 않는다.
- `MenuButton`/`DismissButton`은 일반 마우스·키보드 click을 유지한다. 보조 터치만 pointerdown/up으로 보완하며 영역 밖 해제·cancel은 무시한다. 같은 pointerId의 뒤늦은 click은 중복 실행하지 않는다. 이동 확정·정답 제출 등 진행 버튼에 이 취소 경로를 일괄 적용하지 않는다.
- `Overlay`의 하단 버튼·상단 X·Esc는 동일 callback을 사용한다. footer는 form 밖의 type=button으로 둔다. 기존 읽음 표시·저장·최종 사용자 제스처의 pointer lock 복귀와 위협 정지 규칙을 유지한다.
- 챕터 6의 확인창에서 ‘설정으로 돌아가기’는 제어반으로만 복귀한다. 다른 UI가 남아 있으면 탐색을 재개하지 않으며 닫기로 경로/완료를 확정하지 않는다.
- 기존 조이스틱 회귀 검사도 새 터치 시작→드래그 방식으로 변경했다. 게임 상태·월드 충돌·감염자 동선은 이 작업에서 변경하지 않았다.

집중 검사는 명시적인 저장 fixture로 챕터별 모달에 접근한다. 실제 키/마우스/터치를 사용하며 신호 퍼즐의 오답 타이밍과 보조 손가락 해제도 실제 입력으로 발생시킨다. 새 게임부터 모든 선택 분기를 연속 재생한 검사와 구분한다. 실제 모바일 기기·다른 브라우저·신규 플레이어 체감은 별도 확인이 필요하다.

## 직접 확인 순서

1. 모바일에서 좌상단을 드래그해 이동하지 않는지 확인하고, 좌하단 여러 위치와 화면 가장자리에서 터치해 원이 나타나는지 본다.
2. 왼손 이동 중 오른손으로 시점을 돌린다. 오른손만 떼도 이동이 유지되고, 왼손을 영역 밖으로 끌어도 유지되는지 본다.
3. 이동 손가락을 누른 채 휴대폰을 다른 손가락으로 열고, 같은 방식으로 하단 닫기를 탭한다. 닫은 뒤 원래 손가락을 움직이는 것만으로 이동이 재개되면 안 된다. 손을 떼고 새로 터치해야 한다.
4. 버튼을 누른 뒤 밖으로 끌어 해제하거나 터치를 취소해 의도치 않게 닫히지 않는지 확인한다. 앱 포커스를 옮겼다 돌아오면 입력은 비워져야 한다.
5. 전원/승인/제어반을 하단 버튼과 Esc로 각각 닫는다. 닫기만으로 퍼즐 성공·이동 확정·아이템 중복 획득이 없어야 한다. 기존 E·Tab·I·Esc와 재개 클릭도 확인한다.
6. 새로고침 후 위치·단서·전원·진행을 이어가고, WebGL 실패 시 2D에서도 같은 터치를 확인한다.

- 게임/저장/입력 관련 단위·계약 검사 22개 파일, 199개 테스트 통과. 린트·TypeScript/정적 배포 빌드 통과. 기존 대형 Three.js 청크 경고는 남아 있다.
