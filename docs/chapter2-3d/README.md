# 챕터 2 · 1인칭 3D 전환

챕터 1과 같은 전체 화면 HUD·마우스/터치 시점·조준 조사·메뉴 복귀를 대합실, 전기실, 계단 앞에 적용합니다. 현재 챕터 3도 [3D로 확장](../chapter3-3d/README.md)했으며 챕터 4~6은 기존 2D Canvas로 유지합니다. 외부 AI는 비활성입니다.

## 플레이 확인 순서

1. 첫 방을 기존 방식으로 조사·클리어하고 ‘대합실로 이동’을 선택합니다. 뒤쪽 차단문과 대합실 도입 대화를 확인합니다.
2. 역 안내도, 통로 점검창, 개찰구 비상 개방 안내문을 조사합니다. 안내 데스크에서 전기실 열쇠를 얻습니다. E·클릭·터치 버튼은 같은 조준 대상을 사용하며 Tab 휴대폰 / I 소지품 / Esc 닫기·잠금 해제를 유지합니다.
3. 왼쪽 직원 통로는 기존 진입 확인 → 회피 미니게임 → 대합실 복귀입니다. 별도의 새 통로 탐색이나 추격은 만들지 않았습니다. 성공·실패 모두 한 번만 처리하며 기존 피해·복구·폐쇄 대사를 유지합니다.
4. 전기실의 배전반에서 세 장치 중 두 개까지 연결합니다. 세 번째 연결은 기존 UI가 거부합니다. 방송을 켜면 기존 기록을 얻으며 꺼도 기록은 남습니다. 조명을 켜거나 끄면 3D 주 조명과 천장 조명도 바뀝니다. 비상광과 시설 표식은 전원 없이도 유지합니다.
5. 개찰구 전원은 셔터 상승과 실제 통과 구간의 충돌을 함께 변경합니다. 조명이 꺼져 있으면 기존 안내대로 계단 이동은 차단됩니다. 조명·개찰구를 모두 켠 뒤 개찰구에 E로 상호작용합니다.
6. 계단 앞의 기존 발소리 대화를 마치면 챕터 2 완료가 저장됩니다. 승강장 계단에 상호작용하면 챕터 3의 3D 승강장과 기존 도입 대화로 연결됩니다.

## 저장과 판정

기존 저장 키와 버전은 유지하며 선택적인 `view3d`를 추가합니다. `version:1`, 현재 구역, 렌더러 공간의 `position:{x,z}`, `yaw`, `pitch`를 저장합니다. 게임 판정과 충돌은 계속 `world.ts`의 좌표와 reducer가 관리합니다. 좌표 변환은 `firstPerson.ts`에 있으며 대합실은 40단위/m, 첫 방·전기실은 50단위/m, 계단 앞은 45단위/m입니다. 대합실은 기존 논리적 지도와 이동 속도를 유지하면서 첫 방보다 넓게 보입니다.

과거 챕터 2 저장에 유효한 3D 시점이 없으면 진행·체력·배터리·단서·소지품·전원·일회성 사건은 유지하고 현재 구역의 안전 시작점에서 3D 탐색을 시작합니다. 과거의 2D x/y를 곧바로 3D x/z로 취급하지 않습니다. 새 시점도 현재 구역·버전·수치·벽·장치·닫힌 개찰구와 대조해 검증하고, 유효하지 않으면 안전 지점으로 복구합니다. 직원 통로 사건 결과는 기존 복귀 위치로 시점도 갱신하므로 사건 전 위치로 되돌아가지 않습니다. 정상적인 구역 이동은 reducer의 목적지 시작 위치를 사용합니다. 전환 직후 저장에서 구역과 시점이 다르면 안전 위치로 복구합니다.

3D→2D 오류 복귀에서는 현재 진행과 충돌 좌표를 유지합니다. 2D에서 이동하면 오래된 3D 시점을 지우고, 다음 3D 실행 시 안전 지점을 사용합니다. 3D 시점 저장은 게임 아이템·퍼즐·체력·성공을 생성하지 않습니다.

## 구조와 수명

- `FirstPersonExploration.tsx`: 첫 방과 챕터 2의 공통 WebGL·입력·시점·이동·저장·조준·HUD·터치·복귀·정리. `FirstPersonRoom.tsx`는 호환 export입니다.
- `chapter2Scene.ts`: 기존 World 데이터의 시설·벽·가구·문·조명 표현. `firstRoomScene.ts`와 기존 Kenney 벤치·오반장 모델·재질 스타일을 사용합니다.
- `sceneInteraction.ts`: 첫 방과 챕터 2가 공유하는 가까운 조준 대상 및 가림 판정. 벽·장애물과 조사 프록시의 가장 가까운 충돌을 비교합니다.
- `view3d.ts`: 새 저장의 스키마·좌표·구역·충돌 검증. `world.ts`의 동일한 전원 값이 열린 개찰구의 통과 범위와 고정 하우징 충돌을 관리합니다.
- `ExplorationBoundary.tsx`: 지연 로딩 실패 시 재로딩 또는 2D 계속하기를 제공합니다.

절차적으로 생성하는 바닥·벽·장치·문·안내 표식은 네트워크 자산 없이 준비됩니다. 필수 NPC 모델·스킨은 로딩 완료 전 이동·조사를 막고 8초 제한 후 오류·재시도·2D 복귀를 제공합니다. 벤치·대기 애니메이션은 보조 에셋이며 실패하면 기본 가구 형상 또는 정지 인물을 유지하고 소품 재시도를 제공합니다. 구역 이탈/재시도 시 RAF, ResizeObserver, 입력·잠금 이벤트, 3D 메시·재질·텍스처·애니메이션을 정리하고 늦게 도착한 로드 결과도 폐기합니다.

## 검증 명령과 제한

```sh
npm test
npm run build
npm run lint
npm run format:check
FIRST_PERSON_CHECK=chapter2 npm run test:browser:first
FIRST_PERSON_CHECK=resume npm run test:browser:first
FIRST_PERSON_CHECK=shortcuts npm run test:browser:first
npm run test:browser
```

첫 방·챕터 2의 3D 브라우저 검사는 Java 없이 프론트와 Chrome만 실행하고 외부 AI 요청 0회를 검사합니다. 기존 통합 검사는 Java와 Spring 테스트용 실행 파일을 사용하며 기본 2D 모드에서 챕터 1~6 스크립트 흐름을 검증합니다. 두 검사에서 사용하는 저장은 임시 프로필이며 실제 플레이 저장을 초기화하지 않습니다.

실제 Android/iOS GPU, Safari/Firefox, 장시간 발열·메모리·터치 감각은 별도 확인이 필요합니다. 헤드리스 Chrome은 SwiftShader를 사용하므로 실제 기기의 GPU 성능 검증이 아닙니다. 그림자 맵은 사용하지 않으며 기존 3D 청크 크기 경고는 남습니다. 직원 통로의 위험 장면은 기존 미니게임 표현이며 자유 이동 가능한 새 통로 맵은 없습니다. 챕터 3~6의 3D 전환, 새 전투·추격·외부 AI 호출은 포함하지 않습니다.

최종 구도 보강 캡처는 유효한 저장 체크포인트에서 별도로 수행합니다: [같은 시점·조명 OFF](10-hall-final-dark.png), [조명 ON](11-hall-final-lit.png), [360×640](12-hall-360x640.png). 계단 앞 캡처는 최종 계단·안전 난간 형태를 반영해 다시 촬영합니다. 재실행: `FIRST_PERSON_CHECK=chapter2-visual npm run test:browser:first`. 이 시각 검사는 실제 첫 방부터 연결한 전체 플레이 검사를 대체하지 않습니다.

## 수행 결과

- 게임·저장·입력·문맥 계약 및 새 3D 저장/가림 검사: **119개 통과**.
- 빌드·TypeScript·ESLint·Prettier 검사 통과. 3D 지연 로딩 청크 크기 경고는 유지됩니다.
- 첫 방에서 실제로 이어진 챕터 2 3D 플레이: 필수 조사·열쇠, 위험 성공/실패·활성 상태 새로고침·복구, 전원 오답/변경/기록 유지, 개찰구·조명 조건, 저장한 시점 복원, 과거 2D 저장의 안전 지점 복구, 필수 모델 차단/재시도, PC·터치·메뉴, 종료 저장과 챕터 3 2D 연결 통과.
- 구역 반복 왕복/에셋 재시도 후 Canvas 1개와 동일한 입력 리스너 수 확인. 벽·장애물 가림 및 거리 제한은 Three.js 실제 Raycaster를 이용한 단위 검사도 통과.
- 기존 챕터 1~6 통합 브라우저 회귀 통과: NPC 동행/비동행, 챕터 5 응답/무응답, 챕터 6 두 경로, 중간 저장/이어하기, 자원·일회성 처리. 통합 모드는 기존 2D 플레이의 회귀 검사이고, 챕터 1~2의 실제 3D 연결은 별도 검사입니다.
- 공통 탐색 복귀, Tab/I/Esc·한글 입력·입력창·포커스 범위, 최종 360×640 및 390×844 모바일 에뮬레이션과 1280px PC 캡처 검사 통과. 모든 해당 브라우저 검사에서 외부 AI 요청 0회, Runtime 예외 0회.

위 과거 검증 결과와 2D 연결 캡처는 챕터 2 작업 당시의 기록입니다. 현재 챕터 3 연결과 검증은 [챕터 3 3D 기록](../chapter3-3d/README.md)을 따릅니다.
