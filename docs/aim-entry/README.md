# 작은 대상 조준·출입구 방향 개선

## 변경 전후

| 항목           | 이전                                       | 현재                                                                   |
| -------------- | ------------------------------------------ | ---------------------------------------------------------------------- |
| 작은 사물      | 중앙 광선이 판정 영역에 정확히 맞아야 선택 | 기존 보이지 않는 개별 판정 영역과 중앙 주변의 제한된 표본 광선을 사용  |
| 가까운 두 대상 | 중앙 광선의 순간 결과에 의존               | 화면 중앙 근접도·거리로 우선순위 결정, 직전 후보에 작은 유지 여유 적용 |
| 가림·거리      | 중앙 광선에서 검사                         | 모든 보조 광선에서도 동일한 장애물·거리 검사                           |
| 문 재진입      | 구역 기본 위치·각도로 복귀                 | 도착 구역의 해당 출입구 앞, 방 안쪽을 향하는 방향으로 진입             |
| 이어하기       | 저장 시점 검증·복원                        | 유지. 출입구 진입 정책을 실행하지 않고 저장된 위치·yaw/pitch 복원      |

휴대폰은 기존의 넓은 논리 영역 대신 실제 모델 주변의 별도 판정 영역으로 보정해 좌석을 향했는데 휴대폰이 선택되는 경우도 줄였습니다. 게임의 거리 판정·충돌·단서 조건은 유지합니다.

조준 여유는 화면 높이를 기준으로 중앙에서 최대 3.75% 반경 안의 25개 광선으로 제한합니다. 조사 거리 한도는 기존 수치를 유지합니다(월드 평면 거리 60 미만 및 기존 3D 광선 거리). 각 광선은 벽·문·차량·좌석 등의 첫 충돌만 검사합니다. 별도 사물 ID를 합치지 않습니다. 이전 후보도 매 프레임 다시 거리·가림 검사를 통과해야 유지됩니다. E·클릭·모바일 조사 버튼과 대상 이름 HUD는 같은 선택 결과를 사용합니다.

`entryView.ts`는 승인된 게임 상태 전이 후 실제 구역이 바뀐 경우에만 적용합니다. 전기실, 열차 A, 중앙↔후방/선두 객실, 문래역 부스·확인 대기 구역의 기존 문 ID를 참조합니다. 같은 구역에서 메뉴를 열고 닫을 때는 적용하지 않습니다. 구역별 과거 위치 목록을 만들지 않습니다. 최초 챕터 진입은 기존 시작점·방향을 사용하고 자동 탈출 대피소 측면은 방 안쪽을 바라봅니다. 진입 후보는 실제 전원·문·NPC 상태의 `walkable` 검사 후 사용하며 잘못된 위치는 안전 시작점으로 복구합니다. 과거 저장의 기본값·시점 검증은 기존 로더를 유지합니다.

## 검사

- 단위 검사: 작은 인접 대상의 개별 선택·미세 흔들림 유지·의도적 대상 전환, 닫힌 벽 뒤 후보 즉시 해제, 거리 밖 제외. 12개 문 이동 조합의 위치·방향·충돌 안전성, 동일 구역 시점 유지도 검사합니다.
- `FIRST_PERSON_CHECK=aim-entry npm run test:browser:first`: 실제 연속 회차 저장에서 전기실 왕복, 임의 yaw/pitch 저장 복원, 보조 없는 중앙 광선이 휴대폰 판정 영역을 빗나가는 각도에서 새 선택 성공, E·마우스 클릭·모바일 버튼 조사 통과. [관찰값](result.json).
- `FIRST_PERSON_CHECK=episode npm run test:browser:first`: 새 게임부터 엔딩·재열람까지 상태 주입 없이 3D 연속 진행 통과(198초, 자동 입력).
- `FIRST_PERSON_CHECK=episode-controls npm run test:browser:first`: 반복 왕복, 단일 Canvas·리스너 정리, Tab·I·Esc 메뉴와 탐색 복귀, 실제 탭 이탈 시 입력 초기화, 모바일 이동·시점 동시 입력 통과.
- `npm test`: 15개 파일·152개 테스트 통과. 타입 검사·빌드·린트도 통과했습니다.

브라우저 검사는 헤드리스 Chromium/SwiftShader와 모바일 터치 에뮬레이션입니다. `aim-entry`와 `episode-controls`는 `episode`가 저장한 체크포인트 파일을 읽으므로 연속 검사 완료 후 실행합니다. 진행 상태는 검증 전용 브라우저 프로필에만 주입합니다. 실제 사용자 저장은 수정하지 않습니다. 연속 실행과 분기·체크포인트 검사는 구분합니다.

## 남은 제약

작은 보조 영역 밖에서는 조준점을 대상 쪽으로 돌려야 합니다. 시야에 전혀 보이지 않는 사물이나 벽 뒤 사물을 자동 탐색하지 않습니다. 좁은 목표가 표본 광선 사이에 놓이는 극단적인 경우에는 약간 더 조준해야 할 수 있습니다. 출입구 방향은 현재 가상 맵의 문 배치에 맞춘 값이므로 맵 변경 시 재검증이 필요합니다. 실제 iOS/Android·Safari의 조작감은 미검증입니다. 빌드 청크 경고는 유지하며 임계값을 바꾸지 않았습니다.
