# 챕터 7 — 안전하지 않은 대피소

에피소드 2의 첫 구간이다. 기존 에피소드 1의 대피소 도착·결과 스냅샷을 유지하며, 챕터 8과 에피소드 2 전체 결말은 구현하지 않는다. [원래 제안](chapter7-proposal.md)은 설계 기록이고 이 문서는 최종 구현을 설명한다.

## 플레이 순서

1. 완료된 에피소드 1 결과에서 **에피소드 2 시작 · 기존 기록 이어가기**를 누르고 시작을 확인한다. 이미 시작한 저장은 **에피소드 2 이어하기**로 돌아간다. 에피소드 1 결과는 챕터 7의 수집품 메뉴에서 계속 다시 볼 수 있다.
2. 대피소 대응 구획에서 휴식 의자를 사용한다. 체력 최소 30 / 배터리 최소 20까지 한 번만 회복한다. 현재 값이 높으면 유지한다. 도착 시점 결과의 자원 값은 바뀌지 않는다.
3. 반입문·후면 문·물자 안내를 살펴본다. 긴 기록은 정지 대화로 읽으며 수집품에서 다시 확인할 수 있다. 외부 관측창에서 감염자의 접근을 확인한다. 현장 상황과 첫 주장이 공유된 뒤에 관련 추가 질문을 할 수 있다.
4. 관측창에서 대응 규칙과 실패 복구를 읽고 **현장 대응 시작**을 선택한다. 휴식·사전 조사 중에는 시간이 흐르지 않는다.
5. 선반에서 지지대 한 세트를 집는다. HUD와 작은 3D 운반물로 표시한다. 설치 전에는 같은 선반에 반납할 수 있다. 설치점 방문과 확인창 열기만으로는 확정되지 않는다.
6. 두 우선순위 중 하나를 실제 설치 작업으로 확정한다.
   - **입구 우선:** 반입문 설치 → 유지 여유 +120초 → 중앙 우회로 → 수동 윈치 고정핀 해제 → 손잡이 조작으로 후면 개방.
   - **후면 우선:** 후면 설치 → 지름길 개방 → 짧은 연결 통로로 안전측 조작 위치 이동.
7. 중앙 우회로와 후면 지름길이 합쳐진 뒤, 단일 방화문을 지나 별도의 후면 준비 구획으로 들어간다. 두 경로 모두 안쪽 방화문을 닫고 빗장을 고정한다. 이때 먼저 타이머를 종료한다. 동행/단독 준비 대화를 천천히 읽을 수 있다.
8. 후면 준비 확인대와 완료 확인대를 사용해 **다음 이동 준비 완료**를 확정한다. 챕터 7만 완료되며 챕터 8 진입 버튼은 없다.

## 판정·조작

- 기본 활성 여유 180초, 입구 보강 시 한 번만 +120초. 추가 시간은 설치 상태에서 계산하므로 설치 반복으로 충전할 수 없다.
- **시간 압박 완화**를 대응 규칙 창과 실패 화면에서 언제든 선택할 수 있다. 시간 감소를 멈추며 분기·기록·완료에 불이익이 없다.
- 설치 1.5초, 윈치 핀 2초 / 손잡이 4초, 방화문 폐쇄 1.5초 / 빗장 1.5초의 현장 작업이다. 이동·UI·포커스 이탈·탐색 잠금 해제로 중단하면 마지막 확정 단계가 보존된다. 임시 진행률은 저장하지 않는다.
- E/클릭/모바일 상호작용은 같은 대상과 판정을 사용한다. Tab/I/Esc, 동적 조이스틱·감도·FOV·밝기·오디오 설정을 공유한다. 운반 중 추가 감속·카메라 흔들림은 없다.
- `onFieldFrame`의 활성 조건을 재사용한다. 대화·단톡방·메뉴·기록·설정·전환·포커스 이탈·마우스 잠금 복귀 대기 동안 위협과 시간은 정지한다. 프레임 간격을 제한해 백그라운드 복귀 시 밀린 시간을 차감하지 않는다.
- 외부 감염자 한 명은 닫힌 외벽 밖의 제한된 관측 동선만 이동한다. 기존 관절 보행 모델·거리 기반 보행을 재사용하고 실내 플레이어 위치를 입력으로 받지 않는다. 실내 감지·추격·전투·적 추가 생성은 없다. 기존 챕터 2의 추적 FSM을 챕터 7에 그대로 활성화하지 않는다.
- 문 변형·남은 숫자·위험 자막으로 압박을 전달한다. 60/30/15초 안내는 한 번씩만 발생하며 경고음은 기존 음량·음소거 설정을 따른다.

## 저장과 NPC

`last-transfer-save-v1`에 `chapter7` 기본값·정규화를 추가했다. 이전 완료 저장에서 바로 시작할 수 있다. 완료된 챕터 6보다 챕터 7 reducer를 먼저 처리하며, 챕터 7 중에는 결과 화면을 자동으로 다시 열지 않는다. 후속 구역을 이전 챕터 탑승 이력 검증에도 등록해 새로고침으로 과거 진행이 사라지는 것을 막는다.

정규 저장은 물자 소유 위치·선택·윈치/문 확정 단계·누적 활성 시간·실패/완료·시간 완화 선택을 보존한다. 온라인 시각 차이는 사용하지 않는다. 다시 불러온 뒤 기존 시작 화면/클릭 복귀 전에는 진행하지 않는다. 운반/설치 중 새로고침으로 물자가 복제되거나 사라지지 않는다.

만료 시 명확한 실패 화면에서 재시도한다. 이번 시도의 물자·설치·문·시간만 대응 시작 전으로 되돌리고 준비 단계에서 명시적으로 다시 시작한다. 휴식·표시 이름·기존 자원·단서·질문·대화는 보존한다. 실패한 상태 자체도 이어할 수 있다. 체력·배터리 영구 차감은 없다.

동행 여부는 **에피소드 1 스냅샷의 `npcTogether`**를 기준으로 한다. 동행자는 쉬는 의자와 안전 확보 뒤 준비 구획에 고정 배치하며 추종 AI는 없다. 비동행자는 등장시키지 않고 스냅샷의 마지막 확인 위치를 그대로 표시한다. 구조/사망 등 확인되지 않은 결과를 새로 생성하지 않는다.

## 코드와 에셋

- `src/game/chapter7.ts`: 데이터·목표·저장 기본값/정규화.
- `src/game/chapter7Engine.ts`: 자원·설치·문·시간·재시도·완료 판정.
- `src/game/chapter7Scene.ts`: 공통 3D 탐색 렌더러에 연결하는 대피소 표현. 좌표·충돌·상호작용은 기존 `world.ts`/`interaction.ts`/`sceneInteraction.ts`를 사용한다.
- `src/components/Chapter7Panels.tsx`, `useChapter7Field.ts`: 확인 UI와 취소 가능한 현장 작업.
- 새 외부 에셋 다운로드 없음. 기존 로컬 Kenney CC0 생존자와 프로젝트 제작 감염자 보행을 재사용한다. 지지대·윈치·빗장·문은 프로젝트 제작 메시다. 출처는 [에셋 기록](../public/art/README.md)을 따른다.

## 검증과 제약

`npm test`, `npm run lint`, `npm run build:playtest`와 아래 Chrome 검증을 사용한다.

```sh
FIRST_PERSON_CHECK=chapter7 npm run test:browser:first
PRODUCTION_CHECK=1 FIRST_PERSON_CHECK=chapter7 node scripts/verify-browser.mjs
```

브라우저 산출물은 `docs/chapter7-verification/`에 둔다. 계정·키·Spring은 필요 없다. 최저 이동 배율 60%에서 두 경로의 활성 소요 시간을 측정하지만, 자동 길찾기·반복 조작 시간은 신규 플레이어의 판단/방향 감각과 다르다. 180/+120초는 여유를 둔 초기 값이며 사람에게 충분하다고 단정하지 않는다. 시간 완화 옵션을 함께 제공하고 실제 기기·신규 플레이테스트로 후속 조정한다.

실제 수행 결과·최저 배율 측정·캡처와 미확인 항목은 [검증 기록](chapter7-verification/README.md)에 구분한다.
