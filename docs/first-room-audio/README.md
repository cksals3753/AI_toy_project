# 첫 방 사운드 1차 적용

## 범위와 사용법

첫 방만 적용합니다. 시작 화면 또는 플레이 중 `? 조작 도움말`에서 음소거·전체 음량·소리 확인을 사용할 수 있습니다. 기본 음량은 35%이며, 음량과 음소거는 `last-transfer-audio-v1`에 별도로 저장해 새로고침·새 회차에서도 유지합니다. 진행 저장 형식과 기존 소리 자막은 변경하지 않습니다.

| 소리           | 재생 조건                                                                                                         |
| -------------- | ----------------------------------------------------------------------------------------------------------------- |
| 환풍·전기 설비 | 첫 방 플레이 중 낮은 필터 노이즈와 50Hz 설비 울림. 대화·메뉴에서는 낮춰 재생                                      |
| 발걸음         | 키·터치 입력 자체가 아니라 충돌 처리 후 실제 이동 거리를 누적해 재생. 정지·벽 밀기·대화·메뉴에서는 새 발걸음 없음 |
| 정비문         | 실제 탈출 결과로 문이 열리는 순간 한 번 재생. 잠긴 문 조사·암호 오답에는 재생하지 않음                            |

첫 방에는 기존 문 닫힘 사건이 없으므로 임의의 닫힘 소리나 새 사건을 추가하지 않았습니다. 아이템 획득·뒤따르는 발소리·휴대폰 진동·차단문·열차 주행음과 챕터 2~6 사운드는 후속 범위입니다.

소재는 Web Audio API로 로컬 생성한 교체 가능한 합성 초안이며 환경 녹음·상용 음원이 아닙니다. 추가 패키지·외부 음원·AI 호출·마이크 권한은 없습니다. `firstRoomAudio.ts`의 음원 생성 부분과 재생 제어를 통해 이후 녹음 소재로 교체할 수 있습니다.

## 브라우저와 상태 처리

- 실제 클릭·키 입력 후 AudioContext를 준비합니다. 터치는 `pointerup`에서도 재개해 모바일의 재생 제한을 처리합니다.
- 한 개의 오디오 컨텍스트를 사용합니다. 음소거·음량 0은 실제 출력 이득을 0으로 만듭니다.
- 포커스 이탈·첫 방 이탈 때 일회성 소리를 중단하고 오디오 렌더링을 일시정지합니다. 복귀할 때 지난 효과음을 몰아서 재생하지 않습니다.
- 저장 복원 시 이미 완료된 문 개방음을 다시 재생하지 않도록 현재 결과에서 비교를 시작합니다.
- 컨텍스트 종료 시 음원·노드·이벤트·타이머를 정리합니다. 소리 기능이 없거나 재생에 실패해도 기존 탐색과 퍼즐은 계속됩니다.

## 검증

```sh
FIRST_PERSON_CHECK=audio npm run test:browser:first
npm test
npm run build
npm run lint
```

Chrome의 실제 WebAudio 그래프에 검증 전용 분석기를 연결했습니다. 환경음의 0이 아닌 PCM 출력, 음소거 시 RMS 0, 실제 이동의 발걸음 생성, 정지·메뉴 중 추가 생성 없음, 문 개방 이벤트, 실제 브라우저 탭 이탈 시 컨텍스트 정지, 챕터 2 이탈 후 정지, 설정 저장을 확인했습니다. 모바일 390×844 터치 에뮬레이션에서 터치 종료에 따른 잠금 해제·조이스틱 발걸음·음소거도 통과했습니다. 실패 초기 검사는 중지된 분석기가 마지막 버퍼를 보존하는 동작과 모바일의 실제 첫 터치 시점을 구분하도록 수정했습니다.

- 16개 파일·155개 테스트 통과. 설정 오염·저장 접근 실패·WebAudio 미지원의 비차단 처리 포함.
- 타입 검사·프로덕션 빌드·린트 통과. 기존 3D 청크 크기 경고는 유지합니다.
- 브라우저 런타임 예외·외부 AI 요청 0건. 외부 AI 기본 비활성 유지.
- [실측 결과](result.json), [PC 설정](settings.png), [모바일 설정](settings-mobile.png).
- [브라우저 출력 녹음 — 환경음·발걸음 2.5초](room-preview.webm). 테스트가 내부 오디오 출력을 녹음한 파일이며 마이크나 실제 주변 소리는 사용하지 않습니다. 문 소리는 설정의 **소리 확인**으로 들어볼 수 있습니다.

## 남은 확인

헤드리스 Chromium에서 실제 오디오 샘플과 재생 상태를 확인했으며, 스피커·헤드폰으로 직접 듣는 청감·음색·음량 균형 평가는 하지 않았습니다. 실제 iOS/Android·Safari의 재생 정책과 블루투스·스피커 출력도 미검증입니다. 합성 음원은 1차 분위기 조정용이며 실제 기기에서 35% 기본값과 효과음 균형을 확인한 뒤 다른 챕터로 확대합니다.

## 챕터 2 확대 이후

이 문서는 첫 방 최초 적용 시점의 결과입니다. 사용자가 첫 방 음량과 분위기를 직접 확인하고 승인한 뒤 챕터 2로 확장했습니다. 현재 `FIRST_PERSON_CHECK=audio`는 [챕터 2 사운드 검증](../chapter2-audio/README.md)을 실행하며, 위 `chapter2Silent` 결과는 확대 전 기록입니다. 이후 챕터 3–4까지 확대했으며 현재 종료 경계는 챕터 5입니다. 최신 재생 정책은 [챕터 3–4 사운드](../chapter34-audio/README.md)를 참고하세요.

현재 오디오는 챕터 1–6과 엔딩까지 확대했습니다. 최신 범위와 결과 화면의 정지 정책은 [챕터 5–6 사운드](../chapter56-audio/README.md)를 참고하세요. 위 무음 경계는 최초 적용 시점 기록입니다.
