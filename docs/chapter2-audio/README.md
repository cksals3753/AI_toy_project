# 챕터 2 사운드

첫 방 사운드를 사용자가 직접 듣고 승인한 음량·분위기를 기준으로 챕터 2까지 확장했습니다. 기본 35%와 기존 저장 키는 유지합니다. 챕터 3 이후·AI·음성은 추가하지 않습니다.

## 소리와 상태

| 소리             | 실제 재생 기준                                    |
| ---------------- | ------------------------------------------------- |
| 대합실·계단 환풍 | 현재 구역과 탐색 상태                             |
| 전기실 설비      | 현재 구역과 `chapter2.power`의 회로 작동 여부     |
| 발걸음           | 충돌 처리 후 실제 이동 거리, 탐색 중에만          |
| 열쇠             | 소지품에 전기실 열쇠가 처음 추가될 때             |
| 스위치·전원 복구 | 실제 회로 변경 / 조명 회로 꺼짐→켜짐              |
| 개찰구           | 개찰구 회로 꺼짐→켜짐, 월드 문 개방과 동일한 상태 |
| 경고·방화문      | 직원 통로 사건 unseen→active                      |

기존 단일 WebAudio 컨텍스트·환풍 루프를 재사용하고 구역과 전원에 따라 필터·설비 레벨을 부드럽게 바꿉니다. 이전 구역의 루프를 추가 생성하지 않습니다. 구역 이탈 시 진행 중 효과음을 중지합니다. 회로를 실제 껐다 다시 켜면 작동음은 다시 납니다. 실패한 세 번째 회로 선택·재조사·반복 E는 상태 변화가 없으므로 소리가 나지 않습니다. 같은 효과음의 250ms 이내 반복을 억제합니다.

모든 소리는 로컬 WebAudio 노이즈·필터·오실레이터·엔벌로프로 합성하며 외부 음원·다운로드·마이크·라이선스 의존성이 없습니다. 첫 방과 동일한 마스터 볼륨을 사용하고 경고음도 낮은 레벨로 제한합니다. 자막과 시각적 단서는 유지됩니다.

설정은 게임 저장과 분리해 저장합니다. 불러온 게임 상태를 비교의 초기 기준으로 사용해 이미 완료한 사건은 재생하지 않습니다. 탭 숨김·포커스 이탈 시 일회성 소리를 중지하고 컨텍스트를 일시정지합니다. 복귀 시 루프만 재개합니다. 미지원·재생 거절·저장 실패는 게임을 막지 않습니다. UI 중 환경음은 기존 첫 방처럼 감쇠하고 발걸음은 중지합니다.

## 직접 확인 순서

1. 새 게임에서 첫 방을 탈출하고 대합실로 이동: 갑작스러운 음량 상승이나 겹친 루프가 없는지 듣습니다.
2. 안내 데스크에서 열쇠 획득 후 재조사: 획득음은 최초 한 번만 납니다.
3. 직원 통로 진입: 자막과 함께 절제된 경고·방화문 소리. 회피 후 복귀합니다.
4. 전기실 제어반에서 개찰구·조명 회로를 켜고, 끄고, 다시 켭니다. 설비음과 개찰구 상태를 비교합니다. 세 번째 회로 선택 거부에는 소리가 나지 않아야 합니다.
5. 전기실↔대합실 왕복, 메뉴·대화·퍼즐 중 이동, 벽을 향한 이동을 확인합니다.
6. 도움말에서 음소거·음량을 바꾸고, 새로고침·이어하기·탭 이탈 후 복귀합니다. 완료 효과음은 다시 울리지 않아야 합니다.
7. 개찰구 통과→계단→챕터 3: 챕터 3에서는 소리가 멈춥니다.
8. 모바일 터치로 이동·설정 조작을 확인합니다.

## 재현 명령

```sh
FIRST_PERSON_CHECK=audio npm run test:browser:first
FIRST_PERSON_CHECK=chapter2 npm run test:browser:first
npm test
npm run build
npm run lint
```

## 검증 결과

- `npm test`: 17개 파일·160개 테스트 통과. 추가 5개는 키 획득·회로·게이트·직원 통로의 상태 변화, 재조사·저장 복원·거부된 조작의 무음, 챕터 범위 제한을 확인합니다.
- `npm run build`: 타입 검사·프로덕션 빌드 통과. Three.js를 포함한 기존 지연 로드 3D 청크 약 755kB 경고는 유지하며 임계값은 변경하지 않았습니다.
- `npm run lint`, 변경 파일 Prettier 검사, `git diff --check` 통과.
- `FIRST_PERSON_CHECK=audio`: 실제 Chrome WebAudio PCM 출력·환경음·발걸음·음소거·음량 저장·탭 이탈 정지·위험 사건·전원·개찰구·저장 복원·반복 왕복·챕터 3 정지·390×844 터치 잠금 해제 및 발걸음·음소거 통과. 외부 AI 요청 0건, 런타임 예외 0건.
- `FIRST_PERSON_CHECK=chapter2`: 첫 방 실제 진행→대합실 진입, 직원 통로 실패·성공·저장 복원, 전원 오답·용량 제한·변경·성공, 개찰구·조명 상태, 기존 저장 위치 복구, 반복 왕복의 리스너·Canvas 안정성, 에셋 재시도, PC 메뉴·모바일 터치, 계단→챕터 3 연결 통과. 최초 별도 실행에서 첫 방 이동 보조가 물품함 접근에 실패해 중단되었으며, 다른 브라우저 검사 없이 단독 재실행하여 전체 통과했습니다.
- 환경음 RMS: 첫 방 약 0.00320(35%), 대합실 약 0.00140(20%), 전기실 회로 작동 약 0.00277, 전체 회로 정지 약 0.00094(각 20%). 장면·측정 구간별 값이며 사람이 느끼는 음량을 대신하지 않습니다.
- [실측 결과](result.json), [PC 설정](settings.png), [대합실 모바일 설정](settings-mobile.png), [첫 방 기준 출력 샘플](room-preview.webm). 샘플은 기존 기준 음량·환경음·이동의 내부 출력 녹음이며 마이크를 쓰지 않습니다.

브라우저 검사 초기에는 완료 확인창 전에 탐색을 재개하려는 순서와 250ms 중첩 제한을 무시한 소스 개수 기대값을 바로잡아 재실행했습니다. 게임 판정은 변경하지 않았습니다. `result.json`은 합성 오디오의 PCM 분석·출력 상태를 확인한 결과이며, 사람이 스피커로 직접 들었다는 의미는 아닙니다.

## 제약

첫 방의 청감은 사용자 승인 기준입니다. 이번 챕터 2의 최종 음량 균형·음색은 실제 스피커와 헤드폰으로 확인이 필요합니다. 실제 iOS/Android·Safari·블루투스 출력은 미검증입니다. 환경음은 구역 단위이며 위치별 공간 오디오나 문 너머 감쇠는 구현하지 않습니다. 합성음이므로 실제 녹음 음원의 질감과 다릅니다.

## 챕터 3–4 확대 이후

현재 오디오는 챕터 1–6과 엔딩까지 확대했습니다. 최신 범위와 결과 화면의 정지 정책은 [챕터 5–6 사운드](../chapter56-audio/README.md)를 참고하세요. 위 무음 경계는 최초 적용 시점 기록입니다.
