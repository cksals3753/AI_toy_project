# 챕터 5 · 대답 없는 승강장 / 3D

문래역 도착 승강장·안내 부스·확인 대기 구역을 공통 `FirstPersonExploration.tsx`로 탐색합니다. `moonScene.ts`는 표현만 담당합니다. 기존 `chapter5Engine.ts`의 표시 이름·응답 선택·등록 취소·등록 대조·보류·현장 승인·완료 판정과 대화는 그대로 유지합니다. 현재 [챕터 6도 3D로 확장](../chapter6-3d/README.md)했습니다. 아래 2D 연결 설명과 검증 기록은 이전 작업 당시의 보관 기록입니다.

## 플레이 확인 순서

1. 챕터 4의 열린 출입문에서 문래역 진입을 승인하고, 챕터 5 시작과 기존 휴대폰 프로필 확인을 마칩니다. 뒤쪽에는 같은 B-04의 열린 출입문이 있습니다.
2. 신발 무리·전광판 경고·응답 감지기를 조사합니다. 신발은 통행을 막지 않으며 바닥 화살표는 확인 대기 구역 방향을 암시합니다. 방송은 기존 도입 자막과 ‘안내방송 자막’ 재조사로 확인합니다.
3. 감지기 조사와 대화 넘기기는 응답이 아닙니다. 전광판 경고와 감지기 조사 뒤에 선택 버튼을 명시적으로 눌러야 합니다. 선택 직전 차단문 작동 경고도 유지합니다. 실제 마이크는 사용하지 않습니다.
4. **응답**하면 동행 생존자와 확인 대기 구역으로 이동하고 차단문이 닫혀 있습니다. 내부 활성 등록·해제 안내를 조사한 뒤 취소 장치에서 등록을 취소합니다. 잘못된 번호는 수정할 수 있고 자원은 소모하지 않습니다. 열린 차단문에서 승강장으로 복귀합니다.
5. **무응답**이면 승강장에 남습니다. 바깥 점검창은 기존 외부 관찰 기록만 제공하며, 안쪽 취소 장치를 직접 선택할 수 없습니다. 안내 부스로 걸어가 조사합니다.
6. 두 분기 모두 부스의 방송 재생·외부 수신·수동 첨부 원본을 조사합니다. 기존 등록 대조 UI에서 발신 식별자·차량·등록 건·표시 이름을 함께 비교합니다. 시각만으로는 확정하지 않으며 제출자 신원은 공개하지 않습니다.
7. 올바른 등록을 대조하고 외부 유도를 보류합니다. 무응답은 등록 보류, 응답은 취소된 등록의 외부 유도 보류로 기록됩니다.
8. 승강장으로 돌아와 M-12 현장 표식을 별도로 조사합니다. D-02 현장 통행 절차에서 문과 승인 방식을 맞추면 정비문이 열립니다. 등록 처리만으로 자동 개방되지 않습니다.
9. 열린 정비문 앞의 이동 확인과 승인을 마치면 챕터 5 완료를 저장합니다. 별도의 챕터 6 시작 버튼으로 3D 정비 통로에 연결합니다.

## 상태·저장·표현

- 문 개방은 `world.ts`가 기존 `registration`·`routeOpen`에서 계산하며, 3D는 같은 결과로 문을 표시합니다. 열리는 문에는 문틀의 충돌만 남습니다. 구역 이동은 기존 E 조사 방식입니다.
- 응답 후 구역 전환 대화 뒤에는 닫힌 차단문을 보여줍니다. 별도의 강제 이동·밀기·문 애니메이션 타이머를 추가하지 않아 끼임이나 재접속 시 사건 재실행을 피합니다.
- 기존 2D 저장은 자원·단서·이름·응답·등록·NPC·완료를 보존하고 현재 구역의 안전 시작점에서 복구합니다. 새 3D 저장은 구역·x/z·yaw/pitch를 저장하며 현재 문·문틀·NPC·사물 충돌로 검증합니다. 다른 구역의 위치는 재사용하지 않습니다.
- 각 현재 구역에는 동행 시 생존자 모델 하나만 표시합니다. 단독이면 표시하지 않습니다. 기존 도움/초대 기록과 대사를 유지하며 NPC가 선택·취소·퍼즐을 대신 수행하지 않습니다.
- 벽·문·좌석·기둥은 공통 레이 가림 검사에 포함합니다. 점검창 유리는 해당 점검창의 조사 표면이며 다른 구역의 내부 조사 프록시를 생성하지 않습니다.
- E·Tab·I·Esc, UI 중 이동 차단·복귀, 모바일 조이스틱/시점/조사, 로딩 실패·재시도·2D 복귀와 구역 이탈 시 자원 정리는 공통 구현을 사용합니다.
- 새로운 적·초자연 사건·마이크·외부 AI·추종 AI는 없습니다. 신도림과 같은 재질·기존 Kenney CC0 생존자 모델을 사용하고, 신발·표식·설비는 프로젝트 생성 도형과 텍스처입니다. [에셋 기록](../../public/art/README.md)을 참조하세요.

## 검증 실행

```sh
npm run build
npm run lint
npm test
npm run format:check
FIRST_PERSON_CHECK=chapter5 npm run test:browser:first
FIRST_PERSON_CHECK=chapter5-visual npm run test:browser:first
```

`chapter5`는 챕터 4 정차 체크포인트에서 실제 출입문 E 조사·진입 승인·프로필 확인으로 시작합니다. 동행/단독 각각 응답/무응답 네 흐름을 검사합니다. 주요 분기마다 저장을 복원하며 등록 오답/수정, 별도 현장 표식, 통로 승인과 챕터 6 연결을 확인합니다. `chapter5-visual`은 유효한 고정 저장 체크포인트의 시각 검사이며 실제 플레이 검사와 구분합니다. 전체 챕터 회귀는 별도 기존 2D 모드입니다.

## 제약

Chrome 헤드리스/SwiftShader와 Chromium 모바일 에뮬레이션을 사용합니다. 실제 iOS/Android·Safari/Firefox, 실제 GPU 성능·발열·장시간 메모리는 별도 확인이 필요합니다. 사운드는 추가하지 않았으며 방송은 자막·기록으로 제공합니다. 충돌은 기존 2D 사각형이고 객실·구역 이동은 조사 후 전환 방식입니다. 3D 청크 약 746 KB의 빌드 크기 경고가 남습니다. 이번 작업에 챕터 6의 3D 제작은 포함하지 않습니다.
